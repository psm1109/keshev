## 3. 시연 준비와 실행

Windows와 Node.js **24.19.0**을 기준으로 합니다. 받은 프로젝트의 `alekov-starter-0.2.11\on-client` 폴더를 탐색기에서 열고 주소창에 `powershell`을 입력합니다. 다른 위치에서 받은 폴더여도 `package.json`, `tools`, `src`, `student`가 있는 `on-client`를 사용합니다. 별도 외부 npm 패키지 설치는 필요하지 않습니다.

```powershell
Get-Location
Test-Path .\tools\start-alekov.ps1
node --version
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

`Test-Path`가 `True`이고 문법 검사가 오류 없이 끝났는지 확인한 뒤, 서버 창을 열어 둔 채 **http://127.0.0.1:5190/** 에 접속합니다. 포트가 사용 중이면 명령과 접속 주소를 모두 `5191`로 바꿉니다. 다른 프로그램을 종료하지 않습니다. 종료는 서버 실행 창에서 `Ctrl+C`입니다.

이 실행은 로컬 PC 확인용이며 SDP 연결을 생성하지 않습니다. 실제 연결 시연은 운영 측에서 받은 승인된 설정·권한과 해당 실행 절차가 있는 경우에만 수행합니다. 자격 정보는 화면이나 문서에 넣지 않습니다. 구체적인 실행 오류는 아직 보고되지 않아 코드 결함이나 사용자 환경 문제로 확정하지 않습니다. 자세한 문제 대응은 [실행 안내](DASHBOARD_RUN_GUIDE.md)를 따릅니다.

## 4. 핵심 기능 3가지 시연 순서

아래는 **시연할 순서**입니다. 순서가 적혀 있다고 해당 기능의 실제 연결 시연을 모두 완료한 것은 아닙니다.

### ① PC 상태 모니터링

1. 「보호 현황」에서 학생 PC 대시보드를 보여 줍니다. 카드 6개의 항목, `PC 실측`, 마지막 측정 종료 시각을 짚습니다.
2. 「다시 조회」를 눌러 처리 중 문구와 버튼 비활성화, 완료 후 시각·값 갱신을 확인합니다. 순간 수치가 반드시 달라져야 하는 것은 아닙니다.
3. 「10초마다 자동 조회」를 켜서 측정이 쌓이면 CPU·메모리 추이와 기록을 보여 줍니다. 기록을 펼치고, 자료가 5개를 넘었을 때 이전·다음 페이지를 시연합니다. 이후 자동 조회를 끕니다.
4. 이상 징후 근거와 알림을 읽습니다. 높은 사용량이나 경고를 보여 주려고 강제로 부하·공격을 만들지 않습니다. 해당 조건이 없으면 관찰 없음 상태를 그대로 보여 줍니다.

**설명:** “서버가 실행된 PC의 실제 응답을 받아 요약·추이·기록으로 보여 줍니다. PC 실측과 SDP 연결은 별개입니다.”

### ② 보안 기록 탐색

1. 왼쪽 「보안 기록」으로 이동합니다. SDP 연결이 없으면 연결 오류와 재조회·다음 행동 안내를 보여 줍니다. 이 경우 실제 기록 필터 시연은 미수행으로 남깁니다.
2. 승인된 연결로 실제 기록을 받은 경우에만 종류·업무 앱·접근 상태 필터를 바꾸고 사건을 선택해 근거·규칙·상태를 확인합니다. 데이터가 없으면 빈 목록을 그대로 설명합니다.
3. 「기록 다시 불러오기」와 대기 표시를 확인합니다. 업무 앱 메뉴도 함께 보여 줄 경우 실제 수신한 앱만 선택해 요청하며, 요청 오류를 접근 거부 판정으로 설명하지 않습니다.

**설명:** “보안 기록을 읽고 필터링하는 학생 화면입니다. Windows 이벤트 건수와 접속·XDR 사건 자료는 서로 다릅니다.”

### ③ AI 설명·조치 결과 검토

1. 제공 AI 연결 절차와 학생 AI 점검 화면의 역할을 구분합니다. 실제 권한이 준비된 경우 점검 버튼을 눌러 대기·결과를 확인합니다. 연결 점검 성공은 사건 설명 성공이 아닙니다.
2. 기록을 선택하고 AI 설명을 요청합니다. 연결·권한·기록이 없으면 그 안내까지만 보여 줍니다. 성공 응답이 실제로 있는 경우에만 요약·인용 근거·규칙·확인 불가 상태·제안을 대조합니다.
3. 조치 제안은 미실행 상태임을 설명합니다. 이 시연 준비 과정에서는 실제 조치를 실행하지 않았습니다. 별도 승인·실행 근거가 없다면 조치 효과를 시연하려고 실행하지 않고, 결과 확인 범위와 `unknown` 처리를 설명합니다.

**설명:** “AI 설명은 참고 정보입니다. 조치는 별도의 사람 확인을 거치며, ACK나 요청 접수만으로 성공이라고 표시하지 않습니다.”

## 5. 실측·예제·테스트 값 구분과 남은 한계

| 구분 | 설명과 한계 |
|---|---|
| PC 실측 | 앱 서버가 실행된 PC의 값입니다. 다른 PC의 서버에 접속하면 브라우저 PC의 값이 아닙니다. 수치는 시각·PC마다 다릅니다. 용량 단위는 GiB, 디스크는 앱 폴더의 파일시스템 범위입니다. |
| 예제 자료 | `demo`는 설명용 응답이며 실제 사용자·SDP 연결 결과가 아닙니다. 위 명령은 예제 모드를 켜지 않습니다. 테스트의 합성 응답도 실측으로 제시하지 않습니다. |
| 확인 불가·이전 값 | 조회하지 못한 항목은 임의 수치로 채우지 않습니다. 전체 재조회 실패 후 마지막 성공 값이 남으면 이전 값 안내·성공 시각을 함께 읽습니다. |
| 네트워크·Windows 기록 | 인터페이스·IPv4 구성 수로 인터넷 연결 여부·송수신 속도를 판단하지 않습니다. Windows 경고·오류 합계는 침해 탐지 결과가 아닙니다. |
| 기록 보존 | 학생 PC 추이·기록은 현재 페이지 메모리에만 있으며 새로고침 시 사라집니다. 영구 저장 기능으로 소개하지 않습니다. |
| 실제 연동 | SDP 실연결, 실제 업무 앱 판정·XDR 기록 수신, AI 사건 설명 성공, 실제 조치 효과는 이 작업에서 검증 완료하지 않았습니다. 제출 전 연결 검증이 어려웠다는 사용자 설명과 구분해 기록합니다. |
| 테스트 범위 | 아래 테스트는 문법·모의 DOM·제어한 입력의 검증입니다. 브라우저 전체 동작, 모든 반응형 화면, 화면 낭독기 전체 사용성, 서버·네트워크 장애 실험, 설치형 앱·포장 검증을 대신하지 않습니다. |
