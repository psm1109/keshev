# 케셰브 실행 안내 한 장

**목적:** 받은 프로젝트 폴더에서 앱을 켜고, PC 상태 조회·재조회·추이·기록이 동작하는지 확인합니다. 화면은 **상단 상태 카드 6개, 아래 추이와 기록**인 관제 대시보드형입니다. 설치형 앱을 만들거나 포장 명령을 실행하지 않습니다. 기존 프로젝트와 제출물은 그대로 둡니다.

## 1. 프로젝트 폴더와 실행 환경을 확인합니다

Windows 파일 탐색기에서 받은 프로젝트의 `alekov-starter-0.2.11\on-client`를 엽니다. 받은 폴더 이름이 다르다면 `package.json`, `tools`, `src`, `student`가 함께 있는 `on-client`가 실행 위치입니다. **탐색기 주소창에 `powershell`을 입력하고 Enter**를 누른 뒤 아래 명령을 실행합니다.

```powershell
Get-Location
Test-Path .\tools\start-alekov.ps1
node --version
```

`Get-Location`이 의도한 `on-client` 폴더이고 `Test-Path` 결과가 `True`인지 확인합니다. 재현 기준 Node.js는 **24.19.0**이며 `node --version` 결과는 `v24.19.0`입니다. Node가 없으면 기준 버전을 설치한 뒤 새 PowerShell 창에서 다시 확인합니다. 다른 버전이라면 기준 버전을 준비하는 것이 좋습니다. 실행 도구는 22~24도 허용하므로 버전 차이만으로 실패 원인을 단정하지 않습니다. 현재 프로젝트에는 별도 외부 npm 의존성이 없어 `npm install`은 필요하지 않습니다.

## 2. 문법을 확인하고 앱을 실행합니다

같은 PowerShell 창에서 순서대로 실행합니다. 첫 명령이 오류 없이 끝나면 다음 명령으로 진행합니다.

```powershell
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

서버가 준비되면 브라우저에서 **http://127.0.0.1:5190/** 을 엽니다. 실행 창은 닫지 않습니다. `ExecutionPolicy Bypass`는 이번 실행에만 적용하며 전역 설정을 바꾸지 않습니다. 포트 5190이 사용 중이면 다른 프로그램을 종료하지 말고 명령의 `-Port 5190`을 `-Port 5191`로 바꾼 뒤 **http://127.0.0.1:5191/** 로 접속합니다. 종료는 서버 실행 창에서 `Ctrl+C`입니다.

## 3. 첫 화면부터 다음 순서로 확인합니다

1. **첫 조회:** 「보호 현황」의 학생 PC 대시보드에서 첫 조회 대기가 끝나는지 확인합니다. CPU·메모리·디스크·네트워크 구성·Windows 방화벽·Windows 기록 카드 6개와 마지막 측정 종료 시각을 읽습니다. 화면이 좁으면 카드 영역을 가로로 이동합니다.
2. **재조회와 대기:** 대시보드의 「다시 조회」를 누릅니다. 처리 중 대기 문구와 버튼 비활성화가 나타나고 완료 후 값·시각이 갱신되는지 확인합니다. 「10초마다 자동 조회」를 켜면 조회 시작 기준 약 10초 간격으로 반복하며, 화면이 숨겨지면 일시 중지합니다. 확인 후 끌 수 있습니다.
3. **추이와 기록:** 아래 CPU·메모리 그래프와 기록을 확인합니다. 그래프는 최근 12회, 기록은 최대 50개·페이지당 5개입니다. 기록을 펼쳐 상세 값을 읽고 이전·다음 페이지를 확인합니다. 이 자료는 현재 페이지 메모리에만 있어 브라우저 새로고침 시 초기화됩니다.
4. **다른 학생 기능:** 업무 앱·보안 기록 메뉴에서 학생 조회 버튼과 대기·실패 안내를 확인합니다. 상단 「다시 불러오기」는 연결 관련 전체 정보를 다시 조회하며 진행 중인 접속 판정·AI 요청과 일부 결과를 초기화합니다. PC 대시보드의 「다시 조회」와 범위가 다릅니다. 제공 기본 카드는 숨겨져 있습니다.

## 4. 실측·설명용 값과 연결 범위를 구분합니다

- **`PC 실측`:** 브라우저가 아니라 앱 서버를 실행한 PC에서 읽은 값입니다. 용량은 GiB이며 디스크는 앱 폴더가 있는 파일시스템 기준입니다. 수치는 PC와 측정 시각에 따라 달라져 이전 화면과 같을 필요가 없습니다. 네트워크 구성 수는 인터넷·SDP 연결 성공을 뜻하지 않고, Windows 경고·오류 건수는 침해 탐지 결과가 아닙니다.
- **`예제 자료(demo)`:** 실제 연결 결과가 아닌 설명용 응답입니다. 위 실행 명령은 예제 모드를 켜지 않습니다. 조회 실패 시 예시 수치로 대체하지 않습니다. 재조회 실패 후 이전 값이 남으면 `이전 측정값 표시`와 마지막 성공 시각을 함께 확인합니다.
- **SDP·AI:** 위 명령은 로컬 PC 조회용이며 SDP 연결을 만들지 않습니다. `연결 없음`이어도 PC 조회는 가능합니다. 실제 업무 앱·보안 기록은 승인된 SDP 연결 설정이, AI는 별도의 계정 연결·앱 권한도 필요합니다. 설정을 받지 못했다면 확인 불가와 다음 행동 안내까지만 확인하며 실제 연동 성공으로 기록하지 않습니다.

## 5. 막혔을 때의 확인과 기록

| 막힌 지점·표시 | 확인할 내용과 다음 행동 |
|---|---|
| `Test-Path`가 `False` / 파일을 찾지 못함 | 실행 위치가 `on-client`인지 확인한 뒤 그 폴더에서 다시 시작합니다. |
| `node`·`npm.cmd`를 찾지 못함 / 버전 안내 | Node 설치·버전을 확인하고 새 PowerShell 창을 엽니다. 지원 범위를 벗어나면 기준 버전 24.19.0을 사용합니다. |
| 문법 검사 오류 | 실행을 멈추고 오류가 가리키는 파일·줄·문구를 기록합니다. 폴더 확인 문제와 코드 문법 문제를 구분합니다. |
| 포트 사용 중 / 페이지에 접속할 수 없음 | 서버 창이 실행 중인지, 명령의 포트와 주소가 같은지 확인합니다. 포트 충돌이면 위의 5191 절차를 따릅니다. |
| PC 항목이 확인 불가 | 실패 항목과 서버 오류를 기록하고 「다시 조회」합니다. 방화벽·Windows 기록은 권한이나 Windows 조회 상태도 확인합니다. |
| `ENGINE_NOT_CONNECTED` / 연결 없음 | 승인된 SDP 설정 유무를 먼저 확인합니다. 이 로컬 실행만으로 연결되지 않는 것을 코드 결함으로 단정하지 않습니다. |

**현재 원인 판정:** 실제 막힌 단계와 오류 원문은 아직 전달되지 않아 안내 문제인지 코드 문제인지는 미확인입니다. 특정 Workbench 경로·이전 4개 카드·숨겨진 제공 화면을 찾게 하던 안내의 불일치는 수정했으며, 이 문서 작업에서 실행 코드는 변경하지 않았습니다. 문제가 생기면 **막힌 단계 / 실행 명령 / 오류 원문 / Node 버전 / 접속 주소**를 함께 기록하세요. 비밀번호·토큰·설정 파일 내용은 공유하지 않습니다.

수집 방식·단위와 과거 측정·검증 이력은 [PC 측정 참고 자료](PC_MEASUREMENT_REFERENCE.md)에 보존했습니다. 과거 기록은 현재 버전의 재검증이나 SDP 연결 성공을 뜻하지 않습니다.
