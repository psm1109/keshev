# 케셰브 관제 대시보드 실행·확인 안내

이 작업은 기존 `student/extension.mjs`를 이어서 개선했습니다. 프로젝트 폴더·기존 제출물은 삭제하거나 이동하지 않았습니다. 포장 없이 프로젝트 폴더에서 실행하며, 포장 명령은 실행하지 않습니다.

## 추가한 세 기능

| 학생이 개선한 기능 | 동작과 범위 |
|---|---|
| 네 가지 상태 요약 | 학생 상태·알림 표시 영역의 대시보드 상단에 CPU·메모리·디스크 여유·네트워크 구성 카드를 배치합니다. 넓은 화면에서 네 카드가 나란히, 좁은 화면에서 세로로 보입니다. |
| CPU·메모리 추이 | `상태 조회·기록`을 누를 때만 수집합니다. 최근 12회 관측을 그래프와 표로 표시합니다. 가로축은 측정 시각, 세로축은 0~100%입니다. 실패 구간은 선을 잇지 않고 과거 값을 만들어 넣지 않습니다. |
| 조회·이상 징후 근거 기록 | 이 탭에서 수집한 성공·부분 결과·실패와 주의할 관측을 최신순으로 최대 60회 보관합니다. XDR 경보나 침해 판정이 아닙니다. |

제공된 **내 PC 상태**는 시스템 값의 수집 기능입니다. 학생 개선은 해당 제공 API의 응답을 이용한 요약·추이·근거 기록입니다. 기존 로그인·접근 판정·보안 기록·AI·조치 표시 구현도 유지했습니다.

`student/appearance.json`에는 케셰브 이름, 파란 강조색, 밝은 배경과 `student-first` 배치를 설정했습니다. 기존 아이콘을 유지합니다. 허용된 배치가 학생 카드를 앞쪽으로 옮기며, 기존 로그인 영역 등 제공 화면은 남아 있습니다. 네 카드와 아래 추이·기록은 학생 대시보드 내부의 순서입니다.

## 데이터의 출처와 한계

- 모든 수치는 **앱 서버가 실행되는 기기**의 값입니다. Windows PC에서 실행하면 해당 PC, 클라우드에서 실행하면 클라우드 기기의 값입니다. 클라우드 측정을 사용자 PC 실측으로 설명하지 않습니다.
- 앱에 설명용 예시 값이나 가짜 과거 자료를 추가하지 않았습니다. `npm run demo`의 로그인·접속 예제와도 별개로, PC 조회 API는 서버 실행 기기를 측정합니다.
- CPU는 짧은 구간의 사용률입니다. 메모리는 실측 사용량/전체 용량을 비율로 계산하며, 디스크는 앱이 있는 디스크의 여유 용량입니다. 네트워크는 인터페이스·IPv4 구성 개수로, 속도·접속 성공·보안 상태를 뜻하지 않습니다.
- 요청 중·실패 시 이전 측정값을 현재 카드에 남기지 않습니다. 마지막 측정이 60초를 넘으면 카드에 `오래된 값 · 재조회 필요`라고 표시합니다. 과거 관측은 추이·기록에 그대로 남으며 과거 결과라고 표시합니다.
- CPU 또는 메모리 85% 이상, 디스크 여유 10% 미만에 안내를 표시합니다. 사용성 안내를 위한 기준이며 보안 인증·침해 판단 기준이 아닙니다. 앱·파일·시스템 설정을 자동 변경하지 않습니다.
- 네 항목 중 조회하지 못한 항목은 요약에도 `확인 불가`와 사유를 표시합니다. 실패·미확인을 0이나 정상으로 바꾸지 않습니다.
- Windows 방화벽·Windows 기록은 기존 제공 `내 PC 상태`에서 별도로 조회합니다. Linux에서는 해당 항목이 지원되지 않습니다.
- 기록은 이 브라우저 탭의 메모리에만 보관합니다. 메뉴를 바꾸어도 유지되지만 새로고침·탭 닫기·앱 재실행 뒤 다시 열면 초기화됩니다. 자동 수집·외부 전송·파일 저장은 추가하지 않았습니다.
- 실제 SDP·AI 연결 및 기존 과제 제출 결과는 이 대시보드의 조회 성공과 별개입니다.

## 기존 Windows 프로젝트에서 실행

기존 실행 기록의 위치를 기준으로 합니다. 폴더가 없으면 중단하고 실제 프로젝트 폴더를 확인합니다. 새 폴더로 복제하거나 기존 파일을 초기화하지 않습니다.

```powershell
$AppFolder = Join-Path $env:LOCALAPPDATA 'ALEPH\Workbench\projects\케셰브-방어전\alekov-starter-0.2.11\on-client'
if (-not (Test-Path -LiteralPath $AppFolder)) {
  throw '기존 프로젝트 위치를 확인해 주세요.'
}
Set-Location -LiteralPath $AppFolder
node --version
npm run check
npm start
```

기준 Node.js는 24.19.0이며 외부 npm 의존성이 없습니다. PC 브라우저에서 `http://127.0.0.1:5189/`을 엽니다. 포트를 다른 프로그램이 사용하고 있으면 해당 프로그램을 종료하지 말고 다음처럼 다른 포트를 선택합니다.

```powershell
$env:ON_PORT = '5190'
npm start
```

이 경우 브라우저 주소도 5190으로 바꿉니다. 종료는 실행 창에서 Ctrl+C입니다. 같은 폴더에서 다시 `npm start`하면 됩니다. `npm start`는 native-host나 SDP·AI 연결을 자동 구성하지 않습니다. 승인받은 연결 기능이 필요하면 기존 담당자 안내를 따릅니다.

클라우드 작업의 기존 체크아웃에서는 아래처럼 실행합니다. 이 클라우드 수정이 Windows PC 폴더에 자동 반영되는 것은 아니므로 PC에서는 수정한 버전이 있는지 먼저 확인합니다. 기존 미커밋 작업을 덮어쓰는 강제 갱신은 하지 않습니다.

```bash
cd /workspace/keshev/alekov-starter-0.2.11/on-client
npm run check
npm start
```

## 같은 결과를 확인하는 순서

1. 수정한 프로젝트에서 앱을 실행하고 브라우저를 새로고침합니다. 케셰브 이름·파란 테마·학생 우선 배치를 확인합니다.
2. 보호 현황의 `학생 상태·알림 표시`에서 관제 대시보드를 찾습니다. 초기에는 네 카드가 `확인 불가`, 추이·기록은 비어 있어야 합니다.
3. **상태 조회·기록**을 누릅니다. 네 카드의 값, 실제 조회 시각(한국 시간), 출처 문구를 확인합니다. 일부를 읽지 못했다면 사유와 부분 결과를 확인합니다.
4. 몇 초 뒤 한 번 더 누릅니다. 두 측정의 실제 시각과 CPU·메모리 값이 추이 표·그래프에 나타나는지 봅니다. 같은 값이어도 실패가 아닙니다.
5. 메뉴를 바꾸었다 돌아와 기록이 유지되는지 확인합니다. 60초 동안 다시 조회하지 않으면 현재 카드에 재조회 안내가 나타나는지 확인합니다.
6. 실패 확인은 내가 실행한 서버만 Ctrl+C로 종료한 뒤 **상태 조회·기록**을 눌러 봅니다. 실패·확인 불가가 보이고 이전 수치가 현재 카드에 남지 않아야 합니다. 같은 폴더에서 서버를 다시 실행하고 재조회해 복구를 확인합니다.
7. 브라우저 새로고침으로 수집 기록이 초기화되는지 확인합니다. 이 초기화는 기록 저장 기능이 없다는 명시된 동작입니다.
8. 아래 제공 **내 PC 상태**와 학생 대시보드의 개선 부분을 구분해 설명합니다. 별도 요청에서 측정하므로 두 화면의 측정 시각과 순간 값은 다를 수 있습니다.

## 이번 검증 결과

클라우드의 Chromium 브라우저에서 실제 제공 API로 두 번 조회하고 네 카드·추이·메뉴 전환을 확인했습니다. 별도의 검증용 응답으로 조회 중 중복 방지, 실패, 부분 결과, 잘못된 값, 오래된 응답, 예시 출처 거부, 주의 안내, 그래프의 실패 구간, 기록 개수 상한, 60초 경과 표시를 확인했습니다. 검증용 응답은 앱 코드나 학생 화면의 예시 데이터로 넣지 않았습니다.

넓은 화면의 네 카드 가로 배치와 390px 화면의 가로 넘침 여부도 확인했습니다. 문법 검사와 변경 파일의 공백 검사는 통과했습니다. 사용자 Windows PC의 실측·방화벽·Windows 기록·승인된 외부 연결은 이번 클라우드 검증의 결과에 포함하지 않습니다. 키보드·화면 낭독기 전체 검수, 설치형 앱과 포장 검증도 수행하지 않았습니다.
