# 내 PC 상태 대시보드 실행·확인 안내

현재 프로젝트 소스의 「내 PC 상태 대시보드」를 Windows PC에서 다시 실행하고 확인하는 순서입니다. 기존 `student/extension.mjs`를 이어서 개선한 버전을 사용합니다. 학생 파일·기존 제출물·개인 연결 설정을 덮어쓰거나 초기화하지 않습니다.

여기서 **같은 결과**는 같은 화면 구성과 갱신 동작을 뜻합니다. CPU·메모리·디스크·네트워크 수치는 실행 시점과 PC 상태에 따라 달라집니다. 캡처의 수치와 같을 필요는 없습니다.

## 제공 기능과 직접 개선한 부분

| 구분 | 동작과 범위 |
|---|---|
| 제공 「내 PC 상태」 | `src/pc-status.mjs`와 `GET /api/pc/status`가 서버 실행 기기의 CPU·메모리·디스크·네트워크 구성 개수·Windows 방화벽·Windows 기록을 수집합니다. 제공 화면의 「내 PC 확인」과 10초 자동 확인은 학생 대시보드의 버튼·주기와 별개입니다. |
| 학생 대시보드의 PC 구성 | 네트워크 카드에서 송수신 속도와 인터페이스·IPv4 구성 수를 함께 확인합니다. 카드 줄을 가로로 스크롤하면 Windows 방화벽과 최근 24시간 System·Application 경고·오류 건수를 볼 수 있습니다. 5,000건 초과는 일부 집계이며 침해·공격 탐지 결과가 아닙니다. 권한 등으로 읽지 못한 항목은 확인 불가와 사유를 표시합니다. 연결 모드는 상단 공통 표시에서 PC 실측과 별도로 확인합니다. |
| 학생 대시보드의 상태 요약 | CPU·메모리·디스크 사용률을 막대로 표시합니다. 네트워크는 Windows 서버 기기의 업로드를 초록색, 다운로드를 파란색 Mbps로 표시합니다. 넓은 화면에서는 네 카드가 한 행에 배치됩니다. CPU·메모리·디스크는 제공 API를 사용하고, 송수신 속도는 직접 추가한 `src/network-traffic.mjs`에서 측정해 같은 PC API의 `metrics.network.traffic`으로 전달합니다. 제공 네트워크 구성 개수는 유지합니다. |
| 학생 대시보드의 지속 과부하 감지 | CPU·메모리는 각각 85% 이상인 연속 조회를 셉니다. 처음 1~2회는 노란색 카드 테두리·막대와 경고 아이콘으로, 3회째부터는 붉은색 카드·막대와 「사용량이 계속 높습니다」로 표시합니다. 85% 미만이면 해당 항목의 횟수를 초기화합니다. |
| 학생 대시보드의 상세보기 | 「상태 지표」 탭에는 최근 12회 그래프와 직전 조회 대비 변화량을 표시합니다. 「기록」 탭에는 조회 당시 CPU·메모리·디스크·네트워크 속도를 최신순으로 최대 50개 보관하고 페이지당 5개씩 표시합니다. 항목을 펼쳐 상세를 확인하며 실패는 실패로 기록합니다. 새로고침하면 기록이 초기화됩니다. |
| 이상 징후 근거 | PC 실측에서 높은 CPU·메모리 사용률, 낮은 디스크 여유, 꺼진 방화벽 프로필과 조회 불가를 출처·시각·한계와 함께 표시합니다. 오래된 측정과 조회 실패도 구분하며 보안 판정이 아닙니다. |
| 학생 대시보드의 조회·갱신 | 접속 시 최초 1회 조회합니다. 이후 수동 조회 또는 선택한 10초 자동 조회로 갱신합니다. 재조회 중 기존 값·그래프를 유지하고 응답이 도착하면 기존 DOM의 값·속성을 갱신합니다. 실패 사유는 상단 측정 상태 문구에서 확인합니다. |
| 학생 영역의 기기·세션 표시 | 기기·세션 상세는 위쪽 `renderIdentity`에서 표시합니다. 아래쪽 `renderStatus`에서는 같은 상세를 반복하지 않고 PC 대시보드와 알림·도움정보를 표시합니다. 제공 「현재 로그인」·「내 기기」·「내 세션」 카드는 별도 제공 영역입니다. |
| 학생 영역의 알림·도움정보 | 알림과 도움정보를 위아래 별도 영역으로 표시합니다. 코드와 메시지가 모두 같은 알림만 한 묶음으로 표시하며 펼치면 자료별 코드가 나옵니다. 학생 영역의 「도움정보 불러오기」는 제공된 조회 버튼과 같은 조회를 실행합니다. 조회 후 왼쪽 콘솔에는 복사되는 안전한 항목, 오른쪽에는 항목별 요약이 표시되며 제목 옆 화살표로 내용만 접을 수 있습니다. 로그인·기기·세션은 별도 구획으로 표시하며 같은 오류 설명은 한 번만 표시합니다. |
| 프로젝트 화면 개선 | 다크·라이트 모드, 사이드바 하단 해·달 버튼, 중앙 영역 스크롤은 프로젝트의 공통 화면 코드도 직접 변경한 부분입니다. 제공된 측정 기능을 새로 구현한 것으로 계산하지 않습니다. |

주요 파일은 `student/extension.mjs`(대시보드), `student/appearance.json`(앱 이름·색·학생 우선 배치), `public/index.html`·`public/style.css`·`public/app.js`·`public/student-appearance.mjs`(공통 화면·테마 전환), `src/student-appearance.mjs`(모드별 색상 대비 보정), `src/network-traffic.mjs`(추가 송수신 측정)입니다.

처음 사용하는 브라우저는 다크 모드이며, 이전에 라이트 모드를 선택했다면 그 선택을 복원합니다. 캡처와 같은 다크 화면이 필요하면 사이드바 왼쪽 하단의 달 아이콘으로 전환합니다. 현재 다크 모드에서는 해 아이콘이 표시됩니다.

화면 구성은 세로 길이를 줄이는 방향을 우선합니다. 관련 라벨·수치·보조 정보는 가능한 한 같은 행에 배치하고, 화면이 좁을 때만 줄바꿈합니다. 네트워크 그래프의 직전 대비 변화량도 업로드·다운로드 라벨 옆에 표시합니다.

측정 전후의 틀은 고정합니다. 요약 카드는 200px, 상태 지표 카드는 302px 높이이며 그래프 영역은 처음부터 190px를 확보합니다. 넓은 화면에서 요약 네 칸·그래프 세 칸은 각각 균등한 폭을 사용합니다. 빈 막대·그래프에는 실제 값이나 점을 만들어 넣지 않습니다. 경고·조회 불가도 기존 슬롯 안에서 갱신하며, 열 수는 측정값이 아닌 화면 폭에 따라서만 바뀝니다.

주의·설명 문구는 같은 의미를 여러 영역에 반복하지 않습니다. 별도 안내가 필요해 새 문구를 추가할 때는 사용자에게 먼저 확인합니다. 측정값이 오래됐거나 조회에 실패했다는 안내는 상단 측정 상태에서만 표시합니다.

## 데이터의 출처와 한계

- CPU·메모리·디스크는 **앱 서버가 실행되는 기기**의 값입니다. 본인 PC에서 서버를 실행해야 본인 PC의 값을 확인합니다.
- 앱에 설명용 예시 값이나 가짜 과거 자료를 추가하지 않았습니다. `npm run demo`의 로그인·접속 예제와도 별개로, PC 조회 API는 서버 실행 기기를 측정합니다.
- CPU는 짧은 구간의 실측 사용률입니다. 메모리 막대는 사용량 ÷ 전체 용량이며, 디스크 막대는 (전체 용량 − 여유 용량) ÷ 전체 용량입니다. 디스크 제목은 「디스크 여유」지만 막대는 사용 비율을 표시하며, 카드에는 남은 용량도 함께 표시합니다. 학생 대시보드의 용량은 바이트를 1024의 세제곱으로 나눈 이진 단위 GiB로 표시합니다. 제공 「내 PC 상태」의 용량 표기는 별도입니다.
- 표시하는 측정 시각은 서버가 모든 조회를 마친 후 생성한 응답 시각입니다. CPU는 약 200ms 구간을 측정하고 메모리와 디스크 등은 조회 중 서로 다른 시점에 수집하므로 모든 항목의 정확한 동시 측정 시각은 아닙니다. 작업 관리자 등과 비교할 때는 가까운 시각과 같은 디스크를 선택하고 단위 및 측정 범위 차이를 확인합니다.
- 학생 대시보드의 네트워크는 **Windows 앱 서버 기기의 활성 어댑터 송수신량을 약 1초간 측정한 평균 속도**입니다. [.NET 어댑터 통계](https://learn.microsoft.com/en-us/dotnet/api/system.net.networkinformation.ipinterfacestatistics?view=netframework-4.8.1)의 송신·수신 바이트 증가량을 실제 측정 간격으로 나눠 Mbps로 계산합니다. 외부 속도 시험·파일 송수신은 하지 않으며 인터넷 회선 최대 속도를 뜻하지 않습니다. 로컬 네트워크 통신도 포함되고 가상 어댑터가 함께 활성화돼 있으면 중복 집계될 수 있습니다. 루프백·터널은 제외합니다. Windows 이외의 환경이나 조회 실패는 「확인 불가」로 표시하며, 유효한 0 Mbps와 구분합니다. 이전 브라우저 다운로드 추정값으로 대체하지 않습니다.
- 재조회 중 마지막 측정값과 그래프를 유지합니다. 성공 시 새 값·측정 시각·기록을 갱신하고, 실패 시 「갱신 실패 · 마지막 측정값 유지」를 표시합니다. 60초가 지나면 「오래된 기록」을 표시하며, 이전 수치를 현재 실측으로 설명하지 않습니다.
- CPU 또는 메모리 85% 이상, 디스크 여유 10% 미만에 안내를 표시합니다. 사용성 안내를 위한 기준이며 보안 인증·침해 판단 기준이 아닙니다. 앱·파일·시스템 설정을 자동 변경하지 않습니다.
- 네 항목 중 조회하지 못한 항목은 요약에도 `확인 불가`와 사유를 표시합니다. 실패·미확인을 0이나 정상으로 바꾸지 않습니다.
- Windows 방화벽·Windows 기록은 기존 제공 `내 PC 상태`에서 별도로 조회합니다. Linux에서는 해당 항목이 지원되지 않습니다.
- 최근 12회의 그래프 값과 최대 50개의 조회 기록은 이 브라우저 페이지의 메모리에만 보관합니다. 앱 메뉴를 바꿔도 유지되지만 새로고침·탭 닫기·앱 재실행 뒤 다시 열면 초기화됩니다. 새로고침 후에는 최초 1회 조회로 새 측정값을 만듭니다. 측정값의 외부 전송·파일 저장은 추가하지 않았습니다.
- 「10초마다 자동 조회」는 처음에 꺼져 있습니다. 켜면 즉시 조회하고 **조회 시작 시각을 기준으로 10초 간격**으로 다시 시작합니다. 요청이 오래 걸리면 겹치는 조회는 건너뛰고 다음 시각에 시작합니다. 브라우저 탭이 숨겨지면 멈추고 다시 보이면 조회를 재개합니다. 측정 완료 시각은 조회 소요 시간에 따라 조금 달라질 수 있습니다.
- 실제 SDP·AI 연결 및 기존 과제 제출 결과는 이 대시보드의 조회 성공과 별개입니다.

## 기존 Windows 프로젝트에서 실행

이미 이 앱을 실행했다면 **본인이 실행한 서버 창에서만 Ctrl+C로 종료**한 뒤 다시 실행합니다. 서버 코드 변경은 브라우저 새로고침만으로 적용되지 않을 수 있습니다. 다른 프로그램이 사용하는 포트나 프로세스는 종료하지 않습니다.

PowerShell에서 다음 명령을 순서대로 실행합니다. 아래 경로는 현재 작업 폴더이며, 다른 PC에서는 보존한 프로젝트의 실제 `on-client` 경로로 바꿉니다.

```powershell
$AppFolder = Join-Path $env:LOCALAPPDATA 'ALEPH\Workbench\projects\keshev\alekov-starter-0.2.11\on-client'
if (-not (Test-Path -LiteralPath $AppFolder)) {
  throw '기존 프로젝트 위치를 확인해 주세요.'
}
Set-Location -LiteralPath $AppFolder
node --version
npm run check
node --test test/student-layout.test.mjs test/pc-dashboard.test.mjs test/network-traffic.test.mjs test/theme.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost
```

기준 Node.js는 24.19.0이며 실행 도구는 22~24를 허용합니다. 이번 작업 환경에서 확인한 버전은 v24.21.0입니다. 외부 npm 의존성이 없어 이 실행을 위해 `npm install`은 필요하지 않습니다. `npm run check`는 학생 확장 문법만 검사하며, 다음 명령은 대시보드·테마의 코드 테스트입니다.

`-NoNativeHost`는 이번 PC 화면 재현에서 계정 연결 보관소를 자동 준비하지 않기 위한 옵션입니다. 이 실행에는 로그인·SDP·AI 연결이 필요하지 않습니다. 로그인·업무 앱 등의 「연결 없음」 안내와 PC 실측 조회 성공을 구분합니다.

실행 안내가 나오면 PC 브라우저에서 `http://127.0.0.1:5189/`을 엽니다. 다른 프로그램이 5189를 사용하면 다음 명령으로 5190에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

이 경우 브라우저 주소는 `http://127.0.0.1:5190/`입니다. 종료는 실행 창에서 Ctrl+C입니다. 승인받은 연결 기능까지 재현해야 한다면 별도의 기존 담당자 안내를 따릅니다.

실행 도구를 쓰지 않는 개발용 대안은 같은 앱 폴더의 `npm start`입니다. 위 명령과 동시에 실행하지 않습니다. 제공 실행 환경을 사용하는 설치형 앱에는 이 개발용 명령을 대신 적용하지 않습니다.

```powershell
npm start
```

## 같은 결과를 확인하는 순서

지속 과부하 감지는 수동·자동 조회를 모두 포함한 **연속 측정 횟수** 기준이며, 측정 사이의 사용률이나 특정 시간 동안의 연속 과부하를 증명하지 않습니다. 조회 전체 실패는 CPU·메모리 모두, 개별 항목 조회 불가는 해당 항목만 연속 횟수를 초기화합니다. 실측 시각 간격이 60초를 넘거나 같은 시각의 응답이 반복돼도 새 연속 횟수로 시작합니다. 오래된 값이나 갱신 실패 시에는 카드의 경고 색상·문구를 숨기고 상단 측정 상태에서 안내합니다. 새로고침하면 감지 횟수도 초기화됩니다.

1. 「보호 현황」에서 「학생 상태·알림 표시」 안의 **내 PC 상태 대시보드**를 찾습니다. 제공 「내 PC 상태」와 다른 영역입니다. 첫 접속 시 별도 클릭 없이 1회 측정되고 「조회 완료 시각」에 한국 시간과 값이 표시되는지 확인합니다.
   네트워크 카드에서 업로드·다운로드와 네트워크 구성 수를 함께 확인합니다. 카드 줄을 오른쪽으로 스크롤해 방화벽·Windows 기록을 확인합니다. 경고·오류 건수의 침해·공격 탐지 아님 안내와 일부 집계 표시를 확인하고, 접근할 수 없는 항목은 확인 불가와 사유로 표시되는지 확인합니다. SDP 미연결·예시 모드는 PC 실측과 별도로 확인합니다.
2. CPU·메모리·디스크 사용 막대, 디스크 여유 용량과 메모리·디스크의 사용량/전체 용량, 초록색 업로드·파란색 다운로드 Mbps를 확인합니다. 새 송수신 측정은 서버 코드 변경을 포함하므로 기존 서버를 재시작한 뒤 브라우저를 새로고침해야 합니다. 조회 불가 항목은 「확인 불가」와 사유가 보여야 합니다. CPU·메모리가 실제로 85% 이상이라면 첫 1~2회는 「높은 사용량 감지 (85% 이상)」가 노란색으로 표시되고 3회째 붉은색의 「사용량이 계속 높습니다」로 바뀌는지 확인합니다. 카드에는 연속 횟수를 표시하지 않습니다. 85% 미만으로 내려가면 강조가 해제되어야 합니다. 확인을 위해 PC에 일부러 부하를 만들 필요는 없으며, 이 조건은 아래 코드 테스트에서도 검증합니다. 처음 한 번의 그래프는 점 하나이며, 과거 자료를 만들어 채우지 않습니다.
3. 2~3초 후 **상태 조회**를 누릅니다. 버튼은 「갱신 중…」이 되지만 기존 카드 수치·막대·그래프는 사라지지 않아야 합니다. 응답이 오면 측정 시각과 값이 바뀌고 그래프에 점이 추가되는지 봅니다. 연속된 유효 측정은 선으로 연결되며 값이 같으면 수평선도 정상입니다.
4. 현재 수치는 상단 네 카드에서 확인하고, 「상태 지표」에는 중복 수치 없이 CPU·메모리·네트워크의 개별 그래프와 직전 대비 변화량이 표시되는지 확인합니다. CPU·메모리는 0~100%, 네트워크는 Mbps 눈금입니다. 네트워크 그래프는 업로드 초록색·다운로드 파란색 범례와 두 선을 표시하며 동일한 세로축을 사용합니다. 그래프의 점에 마우스를 올리면 해당 조회 시각과 측정값을 확인할 수 있습니다.
5. 「상세보기」의 「상태 지표」와 「기록」 탭을 전환합니다. 기록은 최신순 5개씩 표시되며 행을 펼쳐 당시 상태와 실패 이유를 확인합니다. 「이전」·「다음」으로 페이지를 이동하고, 50회 초과 시 가장 오래된 기록이 제거되는지 확인합니다. 그래프에는 최근 12회가 남습니다.
6. **10초마다 자동 조회**를 켭니다. 즉시 한 번 조회한 뒤 시작 시각 기준 약 10초 간격으로 측정이 시작되고 시각·그래프가 갱신되는지 봅니다. 확인이 끝나면 끕니다. 이미 진행 중인 한 건은 끝날 수 있지만 이후 반복은 없어야 합니다.
7. 자동 조회를 켜고 다른 브라우저 탭으로 이동했다가 돌아옵니다. 숨겨진 동안의 연속 측정을 만들지 않고, 돌아왔을 때 재조회하는지 확인합니다. 이어 자동 조회를 끕니다.
8. 자동 조회를 끈 상태에서 60초 이상 기다립니다. 마지막 측정값은 유지되며 「오래된 기록」이 표시되어야 합니다. 수동 조회하면 새 시각으로 갱신되고 오래된 상태가 해제되는지 확인합니다.
9. 앱의 「업무 앱」 등 다른 메뉴로 이동했다가 「보호 현황」으로 돌아옵니다. 같은 페이지의 측정 기록이 유지되는지 확인합니다. 중앙 영역을 스크롤할 때 상단 바·사이드바가 고정되고, 왼쪽 하단 해·달 버튼으로 테마가 전환되는지도 확인합니다.
10. 실패·복구를 확인하려면 자동 조회를 끄고 **본인이 실행한 서버만 Ctrl+C로 종료**한 뒤, 브라우저를 새로고침하지 않은 채 「상태 조회」를 누릅니다. 마지막 성공 값이 남고 「갱신 실패 · 마지막 측정값 유지」와 실패 사유가 상단에 표시되어야 합니다. 실패 구간은 그래프에서 선을 잇지 않습니다. 같은 실행 명령으로 서버를 다시 켠 후, 열려 있는 화면에서 버튼을 눌러 복구를 확인합니다.
11. 브라우저를 새로고침합니다. 기존 기록과 자동 조회 선택은 초기화되고 최초 1회 조회로 새 기록이 생기는지 확인합니다. 테마 선택은 별도로 저장되므로 유지됩니다.
12. 제공 **내 PC 상태**의 「내 PC 확인」을 눌러 방화벽·Windows 기록을 별도로 확인할 수 있습니다. 제공 카드와 학생 대시보드는 별도 요청이므로 측정 시각·순간 수치가 다를 수 있으며 일치가 필수 조건은 아닙니다.
13. 학생 구현 영역에서 로그인 사용자·기기·세션 구획을 확인합니다. 알림은 같은 코드와 메시지만 묶이며, 항목을 펼치면 자료별 코드를 확인할 수 있습니다. 도움정보의 「불러오기」를 누르고 왼쪽 복사 내용과 오른쪽 요약을 확인한 뒤 제목 옆 화살표로 내용만 접고 다시 펼칩니다. 복사는 사용자가 직접 버튼을 눌렀을 때만 수행됩니다.
14. 내 PC 상태 대시보드 아래에서 이상 징후 근거를 확인합니다. PC 조회 후 실제 관찰 또는 확인 불가가 출처와 시각과 함께 표시되는지 확인합니다.

## 측정 시각과 디스크 용량 확인 및 PC 비교

위의 **기존 Windows 프로젝트에서 실행** 명령으로 서버를 실행하고, **같은 결과를 확인하는 순서**의 1~2번을 마친 뒤 이어서 확인합니다. 앱 서버와 Windows 확인 화면은 같은 PC에서 실행해야 합니다.

1. 학생 대시보드에서 「조회 완료 시각」과 한국 시간 표시를 확인합니다. 이 시각은 전체 조회가 끝난 시각이고, CPU·메모리·디스크가 정확히 같은 순간에 측정되었다는 뜻은 아닙니다.
2. 디스크 카드에서 `사용량 / 전체 용량`이 한 줄로 표시되고, 그 아래에 여유 용량이 표시되는지 확인합니다. 숫자가 잘리면 카드 줄을 가로로 이동해 확인합니다. 용량 단위는 GiB입니다. 표시 값은 실제 PC의 상태에 따라 달라집니다.
3. Windows **작업 관리자 → 성능 → CPU**와 **메모리**를 차례로 열고, 대시보드의 **상태 조회**를 누른 직후 표시되는 값과 비교합니다. 조회 완료 시각과 비교한 시각, 양쪽 값을 기록합니다. CPU는 순간 변화와 측정 구간에 따라 차이가 날 수 있습니다.
4. 파일 탐색기의 **내 PC**에서 앱이 측정하는 드라이브의 **속성**을 열고 여유 공간과 전체 용량을 비교합니다. 드라이브가 다르면 같은 값이 나오지 않습니다. Windows의 바이트 값을 `1024³`으로 나누면 대시보드의 GiB와 같은 기준으로 비교할 수 있습니다.
5. 비교한 날짜·시각, 드라이브, 앱과 Windows의 수치 및 차이를 직접 기록하거나 화면으로 남깁니다. 읽지 못한 항목은 임의의 값 대신 「확인 불가」와 이유를 기록합니다. 이전에 Windows 시스템 정보와 비교한 실측 기록은 [PC 측정값 비교 기록](PC_COMPARISON_RECORD.md)에 있으며, 작업 관리자·디스크 속성 화면을 직접 비교한 결과를 대신하지 않습니다.

## 현재 코드 검증과 실제 실행 확인의 구분

학생 확장 문법 검사와 `test/student-layout.test.mjs`·`test/pc-dashboard.test.mjs`·`test/network-traffic.test.mjs`·`test/theme.test.mjs`는 PC 관찰의 확인 불가·오래됨·조회 실패 구분, 알림과 도움정보, PC 조회 기록 한도와 자동 조회 간격을 확인합니다. 코드 테스트는 DOM 모형·제어된 응답·서버 핸들러를 사용하며 실제 브라우저의 픽셀 배치나 설치형 실행을 인증하지 않습니다. 위 화면 확인 순서는 사용자가 직접 수행할 재현 절차입니다.

현재까지의 최신 개선에는 커밋되지 않은 변경이 포함될 수 있습니다. 같은 결과를 다른 PC에서 재현하려면 해당 파일·테스트를 포함한 작업 버전을 보존하고, 커밋 번호를 기록할 경우 최신 개선이 포함된 커밋인지 확인합니다. 기존 파일을 강제로 되돌리거나 덮어쓰지 않습니다.

설치형 앱은 검증된 제공 화면을 사용합니다. `public/app.js`·`public/style.css`·서버 보정 코드의 로컬 변경이 설치형 앱에도 반영됐다고 가정하지 않습니다. 설치본은 승인된 실행 host의 바로가기로 실행하고, 같은 확인 순서를 실제 완성본에서 별도로 수행해야 합니다. 이번 안내는 포장·배포·승인된 설치형 환경의 검증 완료를 뜻하지 않습니다.

## 이전 버전의 검증 기록 — 현재 버전 재검증 결과 아님

아래는 이 문서에 원래 남아 있던 클라우드 검증 기록을 보존한 것입니다. 수동 조회만 있던 이전 구현의 기록이며, 현재의 네트워크 송수신 속도·10초 반복·값 유지 갱신·테마·고정 스크롤까지 시연했다는 뜻으로 사용하지 않습니다.

클라우드의 Chromium 브라우저에서 실제 제공 API로 두 번 조회하고 네 카드·추이·메뉴 전환을 확인했습니다. 별도의 검증용 응답으로 조회 중 중복 방지, 실패, 부분 결과, 잘못된 값, 오래된 응답, 예시 출처 거부, 주의 안내, 그래프의 실패 구간, 기록 개수 상한, 60초 경과 표시를 확인했습니다. 검증용 응답은 앱 코드나 학생 화면의 예시 데이터로 넣지 않았습니다.

넓은 화면의 네 카드 가로 배치와 390px 화면의 가로 넘침 여부도 확인했습니다. 문법 검사와 변경 파일의 공백 검사는 통과했습니다. 사용자 Windows PC의 실측·방화벽·Windows 기록·승인된 외부 연결은 이번 클라우드 검증의 결과에 포함하지 않습니다. 키보드·화면 낭독기 전체 검수, 설치형 앱과 포장 검증도 수행하지 않았습니다.
