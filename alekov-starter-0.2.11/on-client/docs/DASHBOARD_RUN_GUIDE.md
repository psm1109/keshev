# 케셰브 관제 대시보드 실행·확인 안내

현재 프로젝트 소스의 「케셰브 관제 대시보드」를 Windows PC에서 다시 실행하고 확인하는 순서입니다. 기존 `student/extension.mjs`를 이어서 개선한 버전을 사용합니다. 학생 파일·기존 제출물·개인 연결 설정을 덮어쓰거나 초기화하지 않습니다.

여기서 **같은 결과**는 같은 화면 구성과 갱신 동작을 뜻합니다. CPU·메모리·디스크·네트워크 수치는 실행 시점과 PC 상태에 따라 달라집니다. 캡처의 수치와 같을 필요는 없습니다.

## 제공 기능과 직접 개선한 부분

| 구분 | 동작과 범위 |
|---|---|
| 제공 「내 PC 상태」 | `src/pc-status.mjs`와 `GET /api/pc/status`가 서버 실행 기기의 CPU·메모리·디스크·네트워크 구성 개수·Windows 방화벽·Windows 기록을 수집합니다. 제공 화면의 「내 PC 확인」과 10초 자동 확인은 학생 대시보드의 버튼·주기와 별개입니다. |
| 학생 대시보드의 상태 요약 | CPU·메모리·디스크 사용률을 막대로, 네트워크 다운로드 추정 속도를 Mbps로 표시합니다. 넓은 화면에서는 네 카드가 한 행에 배치됩니다. CPU·메모리·디스크는 제공 API를 사용하고, 속도는 브라우저 연결 정보에서 읽습니다. |
| 학생 대시보드의 지속 과부하 감지 | CPU·메모리는 각각 85% 이상인 연속 조회를 셉니다. 처음 1~2회는 노란색 카드 테두리·막대와 경고 아이콘으로, 3회째부터는 붉은색 카드·막대와 「사용량이 계속 높습니다」로 표시합니다. 85% 미만이면 해당 항목의 횟수를 초기화합니다. |
| 학생 대시보드의 상태 지표 | 탭 버튼 없이 CPU·메모리·네트워크 개별 그래프와 직전 조회 대비 변화량을 바로 표시합니다. 그래프와 접힌 측정표는 최근 12회를 보관·표시합니다. 별도 조회 기록 목록·탭·페이지 이동은 없습니다. |
| 학생 대시보드의 조회·갱신 | 접속 시 최초 1회 조회합니다. 이후 수동 조회 또는 선택한 10초 자동 조회로 갱신합니다. 재조회 중 기존 값·그래프를 유지하고 응답이 도착하면 기존 DOM의 값·속성을 갱신합니다. 실패 사유는 상단 측정 상태 문구에서 확인합니다. |
| 학생 영역의 기기·세션 표시 | 기기·세션 상세는 위쪽 `renderIdentity`에서 표시합니다. 아래쪽 `renderStatus`에서는 같은 상세를 반복하지 않고 PC 대시보드와 알림·도움정보를 표시합니다. 제공 「현재 로그인」·「내 기기」·「내 세션」 카드는 별도 제공 영역입니다. |
| 프로젝트 화면 개선 | 다크·라이트 모드, 사이드바 하단 해·달 버튼, 중앙 영역 스크롤은 프로젝트의 공통 화면 코드도 직접 변경한 부분입니다. 제공된 측정 기능을 새로 구현한 것으로 계산하지 않습니다. |

주요 파일은 `student/extension.mjs`(대시보드), `student/appearance.json`(앱 이름·색·학생 우선 배치), `public/index.html`·`public/style.css`·`public/app.js`·`public/student-appearance.mjs`(공통 화면·테마 전환), `src/student-appearance.mjs`(모드별 색상 대비 보정)입니다.

처음 사용하는 브라우저는 다크 모드이며, 이전에 라이트 모드를 선택했다면 그 선택을 복원합니다. 캡처와 같은 다크 화면이 필요하면 사이드바 왼쪽 하단의 달 아이콘으로 전환합니다. 현재 다크 모드에서는 해 아이콘이 표시됩니다.

## 데이터의 출처와 한계

- CPU·메모리·디스크는 **앱 서버가 실행되는 기기**의 값입니다. 본인 PC에서 서버를 실행해야 본인 PC의 값을 확인합니다.
- 앱에 설명용 예시 값이나 가짜 과거 자료를 추가하지 않았습니다. `npm run demo`의 로그인·접속 예제와도 별개로, PC 조회 API는 서버 실행 기기를 측정합니다.
- CPU는 짧은 구간의 실측 사용률입니다. 메모리 막대는 사용량 ÷ 전체 용량이며, 디스크 막대는 (전체 용량 − 여유 용량) ÷ 전체 용량입니다. 디스크 제목은 「디스크 여유」지만 막대는 사용 비율을 표시합니다. 용량의 GB 표시는 코드에서 1024의 세제곱으로 나눕니다.
- 학생 대시보드의 네트워크는 **이 화면을 연 브라우저의 다운로드 대역폭 추정값**입니다. 실제 송수신 사용량·최대 회선 속도·업로드 속도를 측정한 결과가 아닙니다. 브라우저가 지원하지 않으면 「확인 불가」로 표시합니다. 제공 API의 인터페이스·IPv4 구성 개수와 구분합니다.
- 재조회 중 마지막 측정값과 그래프를 유지합니다. 성공 시 새 값·측정 시각·기록을 갱신하고, 실패 시 「갱신 실패 · 마지막 측정값 유지」를 표시합니다. 60초가 지나면 「오래된 기록」을 표시하며, 이전 수치를 현재 실측으로 설명하지 않습니다.
- CPU 또는 메모리 85% 이상, 디스크 여유 10% 미만에 안내를 표시합니다. 사용성 안내를 위한 기준이며 보안 인증·침해 판단 기준이 아닙니다. 앱·파일·시스템 설정을 자동 변경하지 않습니다.
- 네 항목 중 조회하지 못한 항목은 요약에도 `확인 불가`와 사유를 표시합니다. 실패·미확인을 0이나 정상으로 바꾸지 않습니다.
- Windows 방화벽·Windows 기록은 기존 제공 `내 PC 상태`에서 별도로 조회합니다. Linux에서는 해당 항목이 지원되지 않습니다.
- 최근 12회의 측정값은 이 브라우저 페이지의 메모리에만 보관합니다. 앱 메뉴를 바꿔도 유지되지만 새로고침·탭 닫기·앱 재실행 뒤 다시 열면 초기화됩니다. 새로고침 후에는 최초 1회 조회로 새 측정값을 만듭니다. 측정값의 외부 전송·파일 저장은 추가하지 않았습니다.
- 「10초마다 자동 조회」는 처음에 꺼져 있습니다. 켜면 즉시 조회한 뒤 **조회 완료 후 10초**가 지나면 다음 조회를 시작합니다. 요청이 겹치지 않으며, 브라우저 탭이 숨겨지면 멈추고 다시 보이면 조회를 재개합니다. 앱 안의 메뉴 전환은 브라우저 탭을 숨기는 것과 다릅니다.
- 실제 SDP·AI 연결 및 기존 과제 제출 결과는 이 대시보드의 조회 성공과 별개입니다.

## 기존 Windows 프로젝트에서 실행

이미 이 앱을 실행했다면 **본인이 실행한 서버 창에서만 Ctrl+C로 종료**한 뒤 다시 실행합니다. 서버 코드 변경은 브라우저 새로고침만으로 적용되지 않을 수 있습니다. 다른 프로그램이 사용하는 포트나 프로세스는 종료하지 않습니다.

PowerShell에서 다음 명령을 순서대로 실행합니다. 아래 경로는 현재 작업 폴더이며, 다른 PC에서는 보존한 프로젝트의 실제 `on-client` 경로로 바꿉니다.

```powershell
$AppFolder = Join-Path $env:LOCALAPPDATA 'ALEPH\Workbench\projects\keshev\alekov-starter-0.2.11\on-client'
if (-not (Test-Path -LiteralPath $AppFolder)) {
  throw '기존 프로젝트 위치를 확인해 주세요.'
}
Set-Location -LiteralPath $AppFolder
node --version
npm run check
node --test test/pc-dashboard.test.mjs test/theme.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost
```

기준 Node.js는 24.19.0이며 실행 도구는 22~24를 허용합니다. 이번 작업 환경에서 확인한 버전은 v24.21.0입니다. 외부 npm 의존성이 없어 이 실행을 위해 `npm install`은 필요하지 않습니다. `npm run check`는 학생 확장 문법만 검사하며, 다음 명령은 대시보드·테마의 코드 테스트입니다.

`-NoNativeHost`는 이번 PC 화면 재현에서 계정 연결 보관소를 자동 준비하지 않기 위한 옵션입니다. 이 실행에는 로그인·SDP·AI 연결이 필요하지 않습니다. 로그인·업무 앱 등의 「연결 없음」 안내와 PC 실측 조회 성공을 구분합니다.

실행 안내가 나오면 PC 브라우저에서 `http://127.0.0.1:5189/`을 엽니다. 다른 프로그램이 5189를 사용하면 다음 명령으로 5190에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

이 경우 브라우저 주소는 `http://127.0.0.1:5190/`입니다. 종료는 실행 창에서 Ctrl+C입니다. 승인받은 연결 기능까지 재현해야 한다면 별도의 기존 담당자 안내를 따릅니다.

실행 도구를 쓰지 않는 개발용 대안은 같은 앱 폴더의 `npm start`입니다. 위 명령과 동시에 실행하지 않습니다. 제공 실행 환경을 사용하는 설치형 앱에는 이 개발용 명령을 대신 적용하지 않습니다.

```powershell
npm start
```

## 같은 결과를 확인하는 순서

지속 과부하 감지는 수동·자동 조회를 모두 포함한 **연속 측정 횟수** 기준이며, 측정 사이의 사용률이나 특정 시간 동안의 연속 과부하를 증명하지 않습니다. 조회 전체 실패는 CPU·메모리 모두, 개별 항목 조회 불가는 해당 항목만 연속 횟수를 초기화합니다. 실측 시각 간격이 60초를 넘거나 같은 시각의 응답이 반복돼도 새 연속 횟수로 시작합니다. 오래된 값이나 갱신 실패 시에는 경고 색상을 해제하고 과거 측정임을 표시합니다. 새로고침하면 감지 횟수도 초기화됩니다.

1. 「보호 현황」에서 「학생 상태·알림 표시」 안의 **케셰브 관제 대시보드**를 찾습니다. 제공 「내 PC 상태」와 다른 영역입니다. 첫 접속 시 별도 클릭 없이 1회 측정되고 「마지막 측정」에 한국 시간과 값이 표시되는지 확인합니다.
2. CPU·메모리·디스크 사용 막대, 메모리·디스크의 사용량/전체 용량, 네트워크 추정 Mbps를 확인합니다. 조회 불가 항목은 「확인 불가」와 사유가 보여야 합니다. CPU·메모리가 실제로 85% 이상이라면 첫 1~2회는 「높은 사용량 감지 · 연속 1/3회」·「2/3회」가 노란색으로 표시되고 3회째 붉은색 지속 경고로 바뀌는지 확인합니다. 85% 미만으로 내려가면 강조가 해제되어야 합니다. 확인을 위해 PC에 일부러 부하를 만들 필요는 없으며, 이 조건은 아래 코드 테스트에서도 검증합니다. 처음 한 번의 그래프는 점 하나이며, 과거 자료를 만들어 채우지 않습니다.
3. 2~3초 후 **상태 조회**를 누릅니다. 버튼은 「갱신 중…」이 되지만 기존 카드 수치·막대·그래프는 사라지지 않아야 합니다. 응답이 오면 측정 시각과 값이 바뀌고 그래프에 점이 추가되는지 봅니다. 연속된 유효 측정은 선으로 연결되며 값이 같으면 수평선도 정상입니다.
4. 「상태 지표」에서 CPU·메모리·네트워크의 개별 박스, 직전 대비 변화량, 「측정값 기록 보기」의 시각·정확한 값을 확인합니다. CPU·메모리는 0~100%, 네트워크는 Mbps 눈금입니다. 펼친 측정표가 재조회 후에도 유지되는지 봅니다.
5. 소제목이 「상태 지표」이며, 탭 버튼 없이 그래프가 바로 표시되는지 확인합니다. 별도 조회 기록 목록·페이지 이동 버튼은 없어야 합니다. 12회를 넘겨 조회하면 그래프·측정표에는 최근 12회만 남아야 합니다.
6. **10초마다 자동 조회**를 켭니다. 즉시 한 번 조회한 뒤 조회 완료로부터 약 10초 후 다음 측정이 시작되고 시각·그래프·측정표가 갱신되는지 봅니다. 확인이 끝나면 끕니다. 이미 진행 중인 한 건은 끝날 수 있지만 이후 반복은 없어야 합니다.
7. 자동 조회를 켜고 다른 브라우저 탭으로 이동했다가 돌아옵니다. 숨겨진 동안의 연속 측정을 만들지 않고, 돌아왔을 때 재조회하는지 확인합니다. 이어 자동 조회를 끕니다.
8. 자동 조회를 끈 상태에서 60초 이상 기다립니다. 마지막 측정값은 유지되며 「오래된 기록」이 표시되어야 합니다. 수동 조회하면 새 시각으로 갱신되고 오래된 상태가 해제되는지 확인합니다.
9. 앱의 「업무 앱」 등 다른 메뉴로 이동했다가 「보호 현황」으로 돌아옵니다. 같은 페이지의 측정 기록이 유지되는지 확인합니다. 중앙 영역을 스크롤할 때 상단 바·사이드바가 고정되고, 왼쪽 하단 해·달 버튼으로 테마가 전환되는지도 확인합니다.
10. 실패·복구를 확인하려면 자동 조회를 끄고 **본인이 실행한 서버만 Ctrl+C로 종료**한 뒤, 브라우저를 새로고침하지 않은 채 「상태 조회」를 누릅니다. 마지막 성공 값이 남고 「갱신 실패 · 마지막 측정값 유지」와 실패 사유가 상단에 표시되어야 합니다. 실패 구간은 그래프에서 선을 잇지 않습니다. 같은 실행 명령으로 서버를 다시 켠 후, 열려 있는 화면에서 버튼을 눌러 복구를 확인합니다.
11. 브라우저를 새로고침합니다. 기존 기록과 자동 조회 선택은 초기화되고 최초 1회 조회로 새 기록이 생기는지 확인합니다. 테마 선택은 별도로 저장되므로 유지됩니다.
12. 제공 **내 PC 상태**의 「내 PC 확인」을 눌러 방화벽·Windows 기록을 별도로 확인할 수 있습니다. 제공 카드와 학생 대시보드는 별도 요청이므로 측정 시각·순간 수치가 다를 수 있으며 일치가 필수 조건은 아닙니다.

## 현재 코드 검증과 실제 실행 확인의 구분

현재 버전의 학생 확장 문법 검사와 `test/pc-dashboard.test.mjs`·`test/theme.test.mjs`의 16개 코드 테스트가 통과했습니다. 10초 자동 조회·탭 없는 상태 지표 표시·최근 측정값 12회 보관과 CPU·메모리의 독립적인 3회 연속 과부하 감지·복구·실패 및 측정 공백 초기화도 포함합니다. 이 테스트는 DOM 모형·제어된 응답·서버 핸들러를 사용하며, Windows PC 실측 전체 과정이나 설치형 실행을 인증하지 않습니다. 이 문서 작성에서는 앱을 중단하거나 재실행하지 않았고, 위 화면 확인 순서는 사용자가 직접 수행할 재현 절차입니다.

현재까지의 최신 개선에는 커밋되지 않은 변경이 포함될 수 있습니다. 같은 결과를 다른 PC에서 재현하려면 해당 파일·테스트를 포함한 작업 버전을 보존하고, 커밋 번호를 기록할 경우 최신 개선이 포함된 커밋인지 확인합니다. 기존 파일을 강제로 되돌리거나 덮어쓰지 않습니다.

설치형 앱은 검증된 제공 화면을 사용합니다. `public/app.js`·`public/style.css`·서버 보정 코드의 로컬 변경이 설치형 앱에도 반영됐다고 가정하지 않습니다. 설치본은 승인된 실행 host의 바로가기로 실행하고, 같은 확인 순서를 실제 완성본에서 별도로 수행해야 합니다. 이번 안내는 포장·배포·승인된 설치형 환경의 검증 완료를 뜻하지 않습니다.

## 이전 버전의 검증 기록 — 현재 버전 재검증 결과 아님

아래는 이 문서에 원래 남아 있던 클라우드 검증 기록을 보존한 것입니다. 수동 조회만 있던 이전 구현의 기록이며, 현재의 네트워크 추정 속도·10초 반복·값 유지 갱신·테마·고정 스크롤까지 시연했다는 뜻으로 사용하지 않습니다.

클라우드의 Chromium 브라우저에서 실제 제공 API로 두 번 조회하고 네 카드·추이·메뉴 전환을 확인했습니다. 별도의 검증용 응답으로 조회 중 중복 방지, 실패, 부분 결과, 잘못된 값, 오래된 응답, 예시 출처 거부, 주의 안내, 그래프의 실패 구간, 기록 개수 상한, 60초 경과 표시를 확인했습니다. 검증용 응답은 앱 코드나 학생 화면의 예시 데이터로 넣지 않았습니다.

넓은 화면의 네 카드 가로 배치와 390px 화면의 가로 넘침 여부도 확인했습니다. 문법 검사와 변경 파일의 공백 검사는 통과했습니다. 사용자 Windows PC의 실측·방화벽·Windows 기록·승인된 외부 연결은 이번 클라우드 검증의 결과에 포함하지 않습니다. 키보드·화면 낭독기 전체 검수, 설치형 앱과 포장 검증도 수행하지 않았습니다.
