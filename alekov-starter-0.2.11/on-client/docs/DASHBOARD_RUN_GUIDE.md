# 내 PC 상태 대시보드 실행·확인 안내

이 문서는 포장하지 않은 프로젝트 폴더 실행을 재현하는 절차입니다. 같은 결과란 화면 구성과 조회 동작을 뜻하며, 실측 수치는 실행 시각과 PC 상태에 따라 달라집니다. 기존 프로젝트·제출물은 삭제하거나 옮기지 않습니다.

## 제공 기능과 학생 구현

| 구분 | 현재 동작 |
|---|---|
| 제공 「내 PC 상태」 | `src/pc-status.mjs`와 `GET /api/pc/status`가 앱 서버 기기의 CPU, 메모리, 앱이 있는 디스크, 네트워크 인터페이스·IPv4 구성, Windows 방화벽과 이벤트 기록을 읽습니다. 보안 설정은 변경하지 않습니다. |
| 학생 대시보드 | `student/extension.mjs`가 제공 PC 응답을 네 칸씩 보이는 가로 카드로 정리합니다. CPU·메모리·디스크 막대, CPU·메모리 추이, 최대 50개 조회 기록(페이지당 5개), 10초 자동 조회와 연속 높은 사용량 표시를 제공합니다. 여섯 카드는 가로로 이동해 확인합니다. |
| Windows 기록 | System·Application의 최근 24시간 경고·오류 합계를 표시합니다. 최근 5,000건만 집계된 경우 일부 집계라고 표시합니다. 화면에는 “이 건수는 침해나 공격 탐지 결과가 아닙니다”라고 적습니다. |
| SDP 상태 | PC 측정과 분리해 제공 세션 조회 결과를 뱃지로 표시합니다. 연결 모드의 활성 세션이 확인되면 초록색 `SDP 연결됨`, 연결 없음 오류가 확인되면 빨간색 `SDP 미연결`, 그 밖에는 중립색 `SDP 연결 상태 확인 불가 · 사유`입니다. PC 조회 성공만으로 SDP 연결을 주장하지 않습니다. |
| 화면 배치 | 학생 로그인 표시 아래에 제공 「현재 로그인」을 둡니다. 제공 「AI 연결」은 학생 AI 연결 표시 위에, 제공 「AI 연결 점검」은 그 아래에 둡니다. 제공 카드의 내용과 버튼 동작은 유지합니다. |

현재 제공 API의 네트워크 값은 인터페이스 수와 IPv4 구성 수입니다. **네트워크 연결 여부, 사용률, 업로드·다운로드 속도는 포함되지 않습니다.** 학생 카드에는 `연결 상태: 확인 불가 · 제공 API에서 연결 상태를 제공하지 않음`으로 표시합니다. 인터페이스나 IP가 있다고 연결됐다고 판단하지 않습니다. 읽지 못한 항목은 임의 수치 대신 「확인 불가」와 이유를 표시합니다. 화면의 PC 조회는 네트워크·방화벽·Windows 기록을 읽기만 하며 설정을 변경하지 않습니다.

방화벽은 제공 API가 Domain·Private·Public 프로필 세 개의 유효한 값을 모두 확인한 경우에만 세 상태를 전달합니다. 일부 프로필 값이 누락되거나 유효하지 않으면 API가 방화벽 항목 전체를 `확인 불가`로 반환하므로, 학생 화면에서는 나머지 프로필의 원래 값을 복원할 수 없습니다. 이때 임의로 켜짐·꺼짐을 표시하지 않고 전체 `확인 불가`와 제공된 이유를 표시합니다.

## PC 실측과 예시 값 구별

- 학생 PC 카드의 `PC 실측`은 **앱 서버를 실행한 PC**에서 제공 API가 읽은 값입니다. 다른 PC에서 서버를 실행하면 이 브라우저를 연 PC의 값이 아닙니다.
- `조회 완료 시각`은 서버가 여러 항목의 수집을 마친 시각입니다. CPU, 메모리, 디스크가 정확히 같은 순간에 측정됐다는 뜻은 아닙니다.
- 메모리·디스크 용량은 바이트를 1024³으로 나눈 **GiB**입니다. 디스크 막대는 사용 비율이며 카드에는 남은 용량도 표시합니다.
- 로그인·연결 영역이 `예제 자료 (demo)`이면 설명용 값입니다. PC 카드에 예시 수치를 만들어 넣지 않습니다. SDP 상태도 예제 자료를 실제 연결로 표시하지 않습니다.
- 화면의 실측 값과 Windows 작업 관리자·디스크 속성을 가까운 시각에 직접 비교해 기록하는 절차는 아래에 있습니다. 현재 코드의 표시만으로 그 비교를 마쳤다고 주장하지 않습니다.

## 수집 경로·단위·측정 범위의 근거

`src/server.mjs`의 `GET /api/pc/status`는 `src/pc-status.mjs`의 `readPcStatus({signal, directory: assetsRoot})`를 호출합니다. 학생 화면은 이 API의 `source: local-pc`, 스키마와 측정 시각을 검증한 뒤 표시합니다. 출처 문자열만으로 실측을 증명하는 것이 아니라 아래 수집 코드와 실제 Windows 조회 결과를 함께 근거로 사용합니다.

| 항목 | 서버 수집 방식 | 단위·계산·범위 |
|---|---|---|
| CPU | `os.cpus()`를 두 번 읽고 그 사이 200ms 대기 | 전체 논리 CPU의 누적 시간 차이에서 `100 × (1 − idle 차이 / 전체 시간 차이)`를 계산한 %. `sampleMs: 200`은 설정한 대기 시간이며 실제 경과 시간이 정확히 200ms라는 증거는 아닙니다. |
| 메모리 | `os.totalmem()`, `os.freemem()` | 바이트 단위의 전체 물리 메모리와 여유 메모리. 사용량은 전체−여유, 사용률은 사용량/전체×100입니다. 화면 용량은 바이트/1024³인 GiB입니다. |
| 디스크 | `statfs(assetsRoot)` | 앱 서버의 정적 파일 폴더가 있는 파일시스템만 읽습니다. 전체는 `blocks × bsize`, 사용 가능한 여유는 `bavail × bsize` 바이트입니다. 모든 드라이브 합계나 디스크 I/O 사용률이 아닙니다. |
| 네트워크 구성 | `os.networkInterfaces()` | 내부 루프백을 제외한 인터페이스 수와 IPv4 구성 수. 인터넷 연결 여부·SDP 연결·송수신 속도를 뜻하지 않습니다. |
| 방화벽 | `Get-NetFirewallProfile` | Domain·Private·Public 프로필의 Enabled 값만 조회합니다. 세 프로필의 값이 모두 유효해야 표시하며 규칙별 차단 효과를 검증하지 않습니다. |
| Windows 기록 | `Get-WinEvent` | 조회 시점 기준 최근 24시간의 System·Application, 오류(Level 2)·경고(Level 3) 합계입니다. 합계가 5,000건을 넘으면 최신 5,000건의 일부 집계로 표시합니다. |
| 시각 | 모든 수집 작업 종료 후 `clock().toISOString()` | `measuredAt`은 UTC ISO 시각이며 화면에서 한국 시간으로 변환합니다. 각 항목의 개별 측정 시각이나 수집 시작 시각이 아닙니다. 서버 PC의 시스템 시계 정확성은 별도 전제입니다. |

CPU·메모리는 짧은 시간에도 변합니다. 작업 관리자는 갱신 주기와 계산 방식도 다를 수 있으므로 순간 수치가 완전히 같아야 한다는 기준을 사용하지 않습니다. 전체 용량은 같은 대상·단위로 비교하고, 사용량은 양쪽 시각과 차이를 함께 기록합니다.

## 재조회 실패 시 이전 측정값 표시

정상 조회가 한 번이라도 성공한 뒤 전체 재조회가 실패하면, 카드에는 마지막 성공 값을 보존하고 상태 줄에 `내 PC 상태 다시 조회 실패 · 이전 측정값 표시`와 원인·다음 행동을 표시합니다. `마지막 측정 종료 시각`은 실패 시각으로 바꾸지 않고 마지막 성공 시각을 유지합니다. 60초가 지난 값에는 `오래된 기록`도 표시합니다.

최초 조회부터 실패했다면 보존할 값이 없으므로 이전 측정값이라고 안내하지 않습니다. 정상 응답에서 특정 항목만 `unavailable`이면 해당 항목은 이전 수치 대신 `확인 불가`로 바뀝니다. 이후 전체 재조회가 성공하면 실패 안내를 지우고 새 값과 새 시각을 표시합니다. 기록·그래프는 현재 페이지 메모리에만 유지됩니다.

## 2026-10-31 로컬 실측 및 실패 표시 확인

프로젝트의 로컬 서버 `http://127.0.0.1:5189/api/pc/status`를 실제 조회하고, 같은 PC에서 Windows CIM과 `Get-Volume`을 읽기 전용으로 조회했습니다. API의 `source`는 `local-pc`, 스키마는 `aleph.on.pc-status.v1`이었습니다.

- API 요청 구간: 한국 시간 11:35:26.484~11:35:28.683.
- API 수집 종료 시각: `2026-10-31T02:35:28.652Z`, 한국 시간 11:35:28.652. 요청 구간 안에 있음을 확인했습니다.
- Windows 비교 조회 완료 시각: 한국 시간 11:35:38.603. 명령들은 순차 조회했으며 각 항목을 API와 같은 순간에 읽은 것은 아닙니다.

| 비교 항목 | 실제 PC API | Windows 비교 조회 | 해석 |
|---|---|---|---|
| CPU 사용률 | 26.5% | `Win32_PerfFormattedData_PerfOS_Processor`, `_Total`: 26.0% | 별도 표본의 참고 비교이며 정확한 일치나 오차 보증이 아닙니다. |
| 전체 물리 메모리 | 17,076,363,264 bytes | `Win32_OperatingSystem.TotalVisibleMemorySize × 1024`: 17,076,363,264 bytes | 전체 용량 일치, 약 15.904 GiB. |
| 사용 메모리 | 12,902,952,960 bytes | `(TotalVisibleMemorySize − FreePhysicalMemory) × 1024`: 12,922,507,264 bytes | 약 12.017/12.035 GiB. 시점이 다른 값 사이에 약 18.648 MiB 차이. |
| C: 전체 용량 | 991,995,883,520 bytes | `Get-Volume -DriveLetter C`의 Size: 991,995,883,520 bytes | 전체 용량 일치, 약 923.868 GiB. 이 실행의 앱 폴더는 C:에 있습니다. |
| C: 여유 용량 | 278,135,246,848 bytes | `Get-Volume`의 SizeRemaining: 278,135,046,144 bytes | 순차 조회 사이 196 KiB 차이. 사용자 권한·예약 공간 등에 따라 다른 API의 여유 용량 정의도 확인해야 합니다. |

실제 API는 방화벽 세 프로필 켜짐과 Windows 기록 경고 25건·오류 47건, `truncated: false`도 반환했습니다. 이 두 항목은 별도 Windows 명령과 독립 대조하지 않았으므로 수치 일치 검증 완료로 보지 않습니다. 작업 관리자 GUI와 디스크 속성을 직접 비교하거나 화면 캡처를 확보한 결과도 아닙니다. 해당 수동 절차는 아래 확인 순서 7번으로 별도 수행합니다.

재조회 실패 표시는 기존 `test/pc-dashboard.test.mjs`의 DOM fixture를 사용한 임시 검증으로 확인했습니다. 실제 서버나 네트워크를 중단하지 않고 응답을 제어했으며 앱 코드에 예시 값을 추가하지 않았습니다. 측정 상태 줄은 SDP 뱃지와 혼동하지 않도록 `pc-measurement-status` ID로 확인했습니다.

- 정상 조회 → 전체 실패: CPU 값과 마지막 성공 시각 유지, `이전 측정값 표시`, 원인·다음 행동 안내 확인.
- 실패 → 정상 재조회: 새 CPU 값 반영과 실패 안내 제거 확인.
- 최초 조회 실패: 조회 실패 안내가 나오며 이전 값이 있다고 표시하지 않음 확인.

이 결과는 수집 경로의 로컬 실측과 실패 시 표시 로직의 검증입니다. 실제 브라우저에서 서버 장애를 재현한 검증, 설치형 앱 검증, SDP 연결 성공 또는 침해 탐지 성공을 뜻하지 않습니다.

## 프로젝트 폴더에서 실행

PowerShell에서 기존 `on-client` 폴더로 이동합니다. 현재 사용 중인 포트의 서버가 본인이 실행한 것이라면 그 창에서 `Ctrl+C`로 종료한 다음 실행합니다. 다른 프로그램의 프로세스는 종료하지 않습니다.

```powershell
$appDir = Join-Path $env:LOCALAPPDATA 'ALEPH\Workbench\projects\keshev\alekov-starter-0.2.11\on-client'
Set-Location -LiteralPath $appDir
node --version
npm run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

브라우저에서 `http://127.0.0.1:5190/`을 엽니다. 포트 5190을 다른 프로그램이 쓰고 있다면 그 프로그램을 종료하지 말고 `-Port 5191`로 실행해 `http://127.0.0.1:5191/`을 엽니다. 포트 5189를 쓰려면 `-Port 5190`을 생략합니다. 이 실행은 별도 SDP 호스트 설정을 주지 않으므로 실제 SDP 연결을 만들지 않습니다. **포장 명령은 실행하지 않습니다.**

## 확인 순서

1. 「보호 현황」의 학생 「내 PC 상태 대시보드」가 접속 시 자동으로 한 번 조회되는지 확인합니다. `PC 실측`과 한국 시간의 조회 완료 시각을 확인합니다. SDP 상태 문구는 PC 실측 상태와 별도로 읽습니다.
2. 한 줄에 CPU·메모리·디스크·네트워크 구성 카드 네 개가 보이고, 가로로 이동하면 Windows 방화벽·Windows 기록 카드가 보이는지 확인합니다. 네트워크 카드의 연결 상태 `확인 불가` 이유와 대시보드의 읽기 전용 안내를 확인합니다. 권한이나 조회 실패가 나면 `확인 불가`와 이유를 기록합니다.
3. Windows 방화벽의 Domain·Private·Public 켜짐/꺼짐을 읽습니다. 화면에서 설정을 바꾸는 동작은 하지 않습니다. Windows 기록에서 System·Application 최근 24시간 합계, 일부 집계 여부, 침해·공격 탐지 결과가 아니라는 안내를 확인합니다.
4. 「상태 조회」를 다시 누릅니다. 기존 값과 카드 틀이 유지되다가 새 값·조회 시각으로 바뀌는지 확인합니다. 「상세보기 → 상태 지표」는 CPU·메모리 변화, 「기록」은 조회 당시 CPU·메모리·디스크 값과 실패 이유를 최신순으로 보여 줍니다. 기록은 한 페이지에 5개, 최대 50개입니다.
5. 필요하면 「10초마다 자동 조회」를 켜고 조회 시작 시각의 간격을 확인한 뒤 끕니다. 페이지가 숨겨지면 반복 조회를 멈춥니다. 강제로 PC 부하를 만들거나 공격·침투를 흉내 내지 않습니다.
6. 학생 로그인 표시 아래의 제공 「현재 로그인」, 학생 AI 연결 표시 위의 제공 「AI 연결」과 아래의 제공 「AI 연결 점검」을 확인합니다. 제공 카드의 버튼은 기존대로 동작해야 합니다.
7. 같은 PC에서 Windows **작업 관리자 → 성능**의 CPU·메모리와 앱 값을 가까운 시각에 비교합니다. 파일 탐색기에서 앱이 위치한 드라이브의 **속성**을 열어 전체·남은 용량을 GiB 기준으로 비교합니다. 날짜·시각, 드라이브, 양쪽 수치와 차이를 직접 기록합니다. 이 확인을 하기 전에는 실제 PC 비교 완료로 적지 않습니다.
8. 브라우저를 새로고침해 기록이 초기화되고 새 실측 조회가 시작되는지 확인합니다. 설치형 앱은 승인된 실행 환경에서 별도로 확인해야 하며, 이 프로젝트 폴더 실행 결과를 설치형 화면의 검증 결과로 대체하지 않습니다.

## 이전 버전의 검증 기록 — 현재 버전 재검증 결과 아님

아래는 이 문서에 원래 남아 있던 클라우드 검증 기록을 보존한 것입니다. 수동 조회만 있던 이전 구현의 기록이며, 현재의 10초 반복·값 유지 갱신·카드 배치까지 시연했다는 뜻으로 사용하지 않습니다.

클라우드의 Chromium 브라우저에서 실제 제공 API로 두 번 조회하고 네 카드·추이·메뉴 전환을 확인했습니다. 별도의 검증용 응답으로 조회 중 중복 방지, 실패, 부분 결과, 잘못된 값, 오래된 응답, 예시 출처 거부, 주의 안내, 그래프의 실패 구간, 기록 개수 상한, 60초 경과 표시를 확인했습니다. 검증용 응답은 앱 코드나 학생 화면의 예시 데이터로 넣지 않았습니다.

넓은 화면의 네 카드 가로 배치와 390px 화면의 가로 넘침 여부도 확인했습니다. 문법 검사와 변경 파일의 공백 검사는 통과했습니다. 사용자 Windows PC의 실측·방화벽·Windows 기록·승인된 외부 연결은 이번 클라우드 검증의 결과에 포함하지 않습니다. 키보드·화면 낭독기 전체 검수, 설치형 앱과 포장 검증도 수행하지 않았습니다.
