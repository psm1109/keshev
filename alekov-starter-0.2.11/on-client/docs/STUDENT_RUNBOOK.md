# 케셰브(KESHEV) 학생 실행 설명서와 시스템 구성도

이 문서는 이 프로젝트의 앱 실행 방법, 구성 요소의 책임 경계, 학생 확장 함수의 역할, 기본 장애 확인 순서를 설명합니다. 포털·안내에서 쓰는 이름은 케셰브입니다. 기존 파일·폴더명과 실행 파일명은 그대로 유지합니다.

> **검증 구분:** 아래 실행 순서와 시작 메시지는 `package.json`, `tools/start-alekov.ps1`, `docs/STUDENT_LAUNCH_GUIDE.md`를 읽어 대조한 내용입니다. 이 문서를 작성할 때 앱을 실행하거나 브라우저를 열지는 않았습니다. 따라서 이 PC의 설치 버전과 실제 시작·연결 결과는 확인되지 않았습니다.

## 1. 앱의 목적과 지원 환경

케셰브는 직원이 본인의 로그인·기기·세션 상태, 업무 앱 접근 판정, 본인 보안 기록과 XDR 경보를 확인하도록 돕는 보안 Agent 앱입니다. AI 설명은 기록의 근거를 읽는 참고 정보이며, 그 자체로 보안 조치나 접근 판정을 실행하지 않습니다.

| 항목 | 확인된 기준 | 확인 범위 |
|---|---|---|
| 실행 환경 | Windows PowerShell에서 제공된 `.ps1` 실행 도구 사용 | 실행 스크립트와 안내 문서에서 확인. 이 PC에서 실행하지 않음 |
| Node.js | 수업 기준 `24.19.0`; 안내 문서는 `22~24` 지원으로 안내 | `package.json`의 `engines.node`는 `24.19.0`으로 지정되어 있고, 실행 스크립트는 주요 버전 22~24를 허용하며 기준 버전이 아니면 안내 메시지를 냄. 설치된 실제 버전은 미확인 |
| 브라우저 | 로컬 PC에서 `http://127.0.0.1:5189/` 열기 | 안내와 실행 스크립트에서 확인. 브라우저 종류·버전은 지정하거나 검사하지 않음 |
| npm 패키지 | `package.json`에 외부 npm 의존성 없음 | README와 AI 설정 안내를 대조. 이 실행 절차에는 `npm install` 단계가 없음 |
| 앱 패키지 | `alekov-client-starter` 버전 `0.2.11` | `package.json`에서 확인 |

`package.json`은 Node.js `24.19.0`을 지정하지만 실행 도구는 Node.js 22~24를 허용합니다. 수업 기준 버전과 로컬 실행 도구의 허용 범위가 다르므로, 재현성 있는 작업에는 안내된 기준 버전을 사용하고 다른 버전에서 생기는 차이는 미확인으로 남깁니다.

## 2. 폴더 구조와 역할

이 문서가 놓인 앱 폴더는 `alekov-starter-0.2.11/on-client/`입니다. 실제 PC에서 시작 틀이 다른 프로젝트 폴더 아래에 있다면, 그 프로젝트의 `on-client`가 앱 폴더입니다.

| 실제 상대 경로 | 역할 |
|---|---|
| `package.json` | 앱 패키지 정보와 `start`, `demo`, `check` 스크립트, Node.js 버전 기준 |
| `tools/start-alekov.ps1` | 앱 폴더·Node.js 버전·포트를 확인하고 `src/server.mjs`를 시작하는 실행 도구 |
| `src/server.mjs` | 로컬 앱 서버 진입점. 제공 코드이며 학생 수정 대상이 아님 |
| `public/index.html`, `public/app.js`, `public/style.css` | 브라우저 UI, 메뉴·화면 갱신 및 서버 요청을 담당하는 제공 코드 |
| `student/extension.mjs` | 학생 표시 기능을 구현하는 확장 파일. 제공 UI가 학생 함수 슬롯을 불러옴 |
| `student/engine-adapter.mjs` | 기존 SDP/에이전트 호스트를 연결할 때 쓰는 어댑터 경계. 기본 export는 `disconnected` |
| `src/engine.mjs`, `src/engine/` | 연결 어댑터 로드, demo 또는 disconnected 경로와 SDP 호스트 연결 경계 |
| `src/ai/`, `vendor/clco-http.mjs`, `public/ai-connect.mjs` | 앱의 AI 연결·승인·서버 측 AI 게이트 통신 경계. 자격·권한 준비는 운영 측 책임을 포함함 |
| `src/vulnerabilities/`, `public/vulnerabilities-view.mjs` | 설치 패키지 메타데이터와 OSV 조회 결과를 처리·표시하는 제공 코드 |
| `docs/` | 학생 실행·연결·장애·단계 안내 |

학생 수정 범위는 과제 단계 안내에 따릅니다. 13~20단계의 학생 표시 작업은 `student/extension.mjs`의 지정 함수가 대상이며, `public/`, `src/`, 제공 서버, 판정 코드와 인증 설정을 임의로 수정하지 않습니다. 이 실행 설명서 작성은 문서 변경이며 함수나 화면은 바꾸지 않습니다.

## 3. 실행·정상 시작·종료·재실행

### 시작 전

1. 파일 탐색기에서 앱 폴더(`on-client`)를 엽니다. 프로젝트의 상위 폴더나 바로가기 위치가 아니라 실제 앱 폴더를 사용합니다.
2. 앱 폴더 주소 표시줄에 `powershell`을 입력하고 Enter를 눌러 그 위치에서 PowerShell을 엽니다.
3. Node.js가 설치되어 있는지 확인합니다. 수업 기준은 `24.19.0`입니다. 실제 설치 버전은 이 문서를 작성하면서 확인하지 않았습니다.

### 시작 명령

앱 폴더에서 다음 명령을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

정상 시작 시 실행 도구가 다음과 같은 안내를 출력해야 합니다.

```text
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
```

그 뒤 브라우저에서 `http://127.0.0.1:5189/`을 엽니다. 시작 메시지는 로컬 서버가 응답했다는 뜻이지, SDP·업무 시스템·AI 게이트에 연결됐다는 뜻은 아닙니다. 기본 실행은 실제 회사 시스템에 연결되지 않은 상태입니다. `-Demo`를 사용하면 예제 자료이며 실제 연결이 아닙니다.

포트 5189를 이미 사용 중이면 해당 프로그램을 종료하지 말고 앱 폴더에서 다른 포트로 실행할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5190
```

이 경우 브라우저 주소도 `http://127.0.0.1:5190/`으로 바꿉니다. 포트 번호는 실행 옵션과 브라우저 주소에서 일치해야 합니다.

### 종료와 재실행

- 일반 실행은 앱을 시작한 PowerShell 창에서 `Ctrl+C`를 눌러 종료합니다.
- 다시 실행할 때는 같은 `on-client` 폴더에서 시작 명령을 다시 실행합니다.
- 앱이 켜져 있는 동안 PowerShell 창을 닫거나 다른 앱 폴더에서 같은 명령을 반복하지 않습니다. 시작·종료는 프로젝트 파일을 수정하는 작업이 아닙니다.

담당자가 별도의 native 호스트 또는 SDP 설정 파일을 발급해 실제 경로와 사용법을 안내한 경우에만 `docs/AI_SETUP_GUIDE.md`, `docs/SDP_HOST_CONNECTION.md`, `docs/CONNECTION_TROUBLESHOOT.md`를 따릅니다. 이 문서에는 예시 경로를 실제 경로인 것처럼 바꾸어 쓰지 않았습니다. 설정 파일 내용·열쇠·토큰을 채팅, 문서, Git 또는 제출물에 넣지 않습니다.

## 4. 글로 쓴 시스템 구성도

```mermaid
flowchart LR
    B[사용자 브라우저<br/>127.0.0.1:5189] -->|같은 출처의 화면·요청| UI[제공 UI<br/>public/index.html · public/app.js]
    UI -->|학생 표시 입력·새 DOM| EXT[학생 확장<br/>student/extension.mjs]
    UI -->|로컬 앱 요청| S[로컬 Node.js 앱 서버<br/>src/server.mjs]
    S --> ENG{기존 엔진 연결 여부}
    ENG -->|운영자가 제공한 연결 설정·호스트가 있을 때| SDP[접근 제어·SDP/XDR 시스템<br/>본인 범위의 승인된 연결]
    ENG -->|기본 실행| DISC[연결 없음(disconnected)]
    ENG -->|명시적으로 예제 실행| DEMO[예제 자료(demo)<br/>실제 연결 아님]
    S -->|운영 권한·앱 연결이 준비된 경우| AI[AI 서비스·통신 경계<br/>src/ai · vendor/clco-http.mjs]
    AI --> G[수업용 AI 게이트웨이<br/>권한·운영 준비에 따라 사용 가능]
    S -->|승인된 공개 패키지의 정확한 버전을 조회할 때| OSV[OSV 공개 취약점 데이터베이스]
    PORTAL[ALEPH 포털<br/>단계 제출·과제 판정] -. 별도 역할 .-> B
```

구성 관계를 읽을 때 다음 경계를 지킵니다.

- 브라우저는 로컬 앱 UI를 사용합니다. 학생 함수는 제공 UI가 전달한 값을 DOM으로 표시하는 확장점이며, 서버·AI 자격을 직접 소유하지 않습니다.
- 기본 엔진 어댑터는 `disconnected`입니다. 운영자가 승인한 연결 설정이 실제 준비된 경우에만 SDP/기존 엔진의 본인 범위 조회가 가능합니다. 예제(`demo`)도 실제 연결이 아닙니다.
- AI 모델 연결 점검과 보안 기록 설명은 별도 흐름입니다. 운영자의 앱 권한과 게이트 준비가 없으면 학생 코드만으로 연결을 만들 수 없습니다. ALEPH의 공식 과제 판정 AI도 앱 내부 AI와 별개입니다.
- OSV는 승인된 공개 패키지의 조회 대상입니다. 조회 결과가 없다는 사실은 앱 전체의 안전 보증이 아닙니다.
- ALEPH 포털은 로컬 앱의 런타임 서버가 아닙니다. 제출된 커밋을 과제 기준으로 판정하는 별도 서비스이며, 이번 단계 안내에 따르면 서버는 문서의 실행 명령을 대신 실행해 검증하지 않습니다.

## 5. 학생 함수와 제공 코드의 경계

`public/app.js`에서 확인되는 학생 슬롯 이름과 공식 단계 계약의 역할은 다음과 같습니다. 아래 설명은 **함수 계약을 요약한 것**이며, 실제 브라우저에서 동작을 확인했다는 뜻은 아닙니다.

| 학생 함수 (`student/extension.mjs`) | 계약상 역할·입력 개요 | 제공 코드와의 경계 |
|---|---|---|
| `renderIdentity` | 로그인한 본인, 현재 기기, 현재 세션 자료를 상태에 맞게 표시 | 제공 UI가 계정 자료를 전달하고 다시 불러오기를 조정 |
| `renderDecision` | 선택한 업무 앱의 접근 판정, 이유, 판정 시각 표시 | 판정은 서버/기존 엔진에서 옴. 허용 판정은 실제 앱 연결 성공을 보장하지 않음 |
| `renderEvents` | 본인 보안 기록 목록·필터·기록 상세의 근거·규칙·상태 표시 | 기록 조회와 제공 범위 안내는 서버·제공 UI가 담당 |
| `renderStatus` | 기기·세션의 로딩/빈 목록/오류, 알림, 전달된 진단 자료 표시 | 진단 조회는 제공 화면이 수행. 학생 함수가 진단 API를 직접 호출하지 않음 |
| `renderAiConnection` | AI 연결 점검의 idle/loading/ok/error 결과 구분 | 연결 승인·서버 점검은 제공 UI와 서버 흐름이며, 점검 성공은 사건 설명 성공이 아님 |
| `renderExplanation` | 선택한 사건의 참고용 설명과 근거·규칙·현재 상태 표시 | 설명 요청·검증은 서버 측 AI 서비스 경계. 설명이나 제안은 실제 조치를 실행하지 않음 |
| `renderAction` | 조치 준비·전달·처리·관측 결과 상태를 구분해 표시 | 과제 계약에 없는 조치 버튼, POST 요청, 인증 티켓을 학생 표시 코드에 추가하지 않음 |
| `renderVulnerabilities` | 패키지 조회 상태, 정확한 설치 버전, 출처·시각·취약점 요약 표시 | 잠금 파일·설치 메타데이터 검사와 OSV 조회는 제공 서버 코드 경계 |

### 제공 UI와 학생 코드의 책임

- 제공 UI는 메뉴와 일반 화면, 데이터 요청·취소·갱신 흐름을 관리하고 학생 확장을 불러옵니다. `public/app.js`의 학생 슬롯 이름은 위 함수들과 연결됩니다.
- 학생 확장은 공식 입력 계약에 따라 상태와 값을 사용자에게 설명합니다. 안전한 DOM 표시에는 과제 계약의 `createElement`와 `textContent` 원칙을 따릅니다.
- `src/server.mjs`, `src/engine.mjs`, `src/engine/`, `src/ai/`, `src/vulnerabilities/`, `vendor/`와 실행 도구는 제공 코드입니다. 이번 문서 작업에서 이 파일들은 변경하지 않았습니다.
- 코드에 함수 이름이 연결되어 있다는 사실만으로 함수별 필수 항목 통과, 서버 연결, 실제 화면 동작을 증명하지는 않습니다.

## 6. 오류·미조회·복구 순서

오류가 보이면 먼저 **무엇이 실패했는지와 상태 코드**를 구분합니다. 빈 결과, 연결 없음, 예제 자료, 확인 불가, 요청 실패를 서로 바꾸어 해석하지 않습니다. 자동으로 요청을 반복하거나 다른 계정·정책·의존성을 바꾸지 않습니다.

| 증상 또는 코드 | 확인 순서 |
|---|---|
| `Node.js 가 없습니다` 또는 버전 안내 | Node.js 기준 버전 `24.19.0`을 확인하고 설치·업데이트를 마친 뒤 새 PowerShell 창에서 다시 시작합니다. 설치된 실제 버전은 이 문서에서 확인하지 않았습니다. |
| `포트 5189 를 다른 프로그램이 쓰고 있습니다` | 다른 프로그램은 종료하지 않습니다. `-Port 5190`으로 실행하고 브라우저도 `:5190`으로 엽니다. |
| 앱 폴더가 아니거나 링크 경로라는 안내 | 실제 `on-client` 폴더에서 실행했는지 확인합니다. 프로젝트 파일을 옮기거나 지우지 않습니다. |
| 앱 서버가 제한 시간 안에 뜨지 않음 | 실행 창의 전체 오류 메시지를 기록해 담당자에게 보여 줍니다. 원인을 확인하기 전 반복 실행이나 파일 삭제를 하지 않습니다. |
| `disconnected`, `demo`, 연결 확인 불가 | 이 상태는 운영 시스템 연결 성공이 아닙니다. 담당자가 연결 설정을 발급했는지 확인하고 기존 연결·demo·unknown을 성공으로 기록하지 않습니다. |
| `ON_AI_PROVISIONING_PENDING` 또는 승인/인증/권한 오류 | 오류 안내에 따라 담당자에게 계정 연결·앱 권한·게이트 준비 상태를 확인합니다. API 키·Workbench 키·토큰을 입력하거나 보내지 않습니다. |
| `CONTRACT_MISMATCH`, `ENGINE_RESULT_UNVERIFIED` 또는 목록 확인 불가 | 응답을 정상이나 빈 목록으로 보지 않습니다. 제공 화면의 `다시 불러오기`를 직접 눌러 한 번 확인하고, 계속되면 오류 코드와 도움정보의 비밀 없는 항목만 담당자에게 전달합니다. |
| OSV `not_configured`, `not_checked`, `partial`, `unverifiable` | 이를 취약점 없음으로 해석하지 않습니다. 조회 허용 목록과 대상은 운영자 담당입니다. 의존성이나 공개 허용 목록을 임의로 바꾸지 않습니다. |
| AI 설명 실패 | AI 설명 실패는 업무 앱 판정이나 보안 기록이 실패했다는 뜻이 아닙니다. 기록은 원래 상태로 두고, 실패 코드와 안내를 따릅니다. 비용이 발생할 수 있는 재요청을 반복하지 않습니다. |

상세 오류 코드는 [`CONNECTION_TROUBLESHOOT.md`](CONNECTION_TROUBLESHOOT.md), AI 승인·권한 흐름은 [`AI_SETUP_GUIDE.md`](AI_SETUP_GUIDE.md), 실행 세부사항은 [`STUDENT_LAUNCH_GUIDE.md`](STUDENT_LAUNCH_GUIDE.md), SDP 연결은 [`SDP_HOST_CONNECTION.md`](SDP_HOST_CONNECTION.md)를 확인합니다.

## 8. 22단계 새 환경 실행 기록

새 빈 폴더에 저장소를 내려받아 위 3장대로 실행한 뒤, 13~21단계별 관찰·근거와 미확인 사유를 [`STUDENT_REPRODUCTION_RECORD.md`](STUDENT_REPRODUCTION_RECORD.md)에 기록합니다. 이 기록은 학생이 직접 관찰한 사실을 남기는 문서이지, 서버가 새 환경에서 실행했다는 증명이 아닙니다.

- 원래 작업 폴더를 보존하고, 새 폴더에서 같은 최종 커밋인지 40자리 전체를 대조합니다. URL·브랜치·커밋·환경·실행 및 재실행 시각을 실제 값으로 기록하며 모르는 값은 미확인으로 둡니다.
- 예제·연결 없음 결과를 실제 연결로 적지 않고, 미확인 항목을 완료로 바꾸지 않습니다. AI 모델 연결 점검은 사건 설명 성공이 아니며, ACK는 실제 조치 효과 관측이 아닙니다.
- 제공 기준 문서의 현재 조치 집행 연결 미완료를 고려해 실제 집행을 성공으로 기록하지 않습니다. 실제 연결 또는 실행을 못 했다면 검증 중인 버전으로 남깁니다.
- 앱이 실행되었다는 학생 진술, 문서·원문 대조, 실제로 직접 관찰한 로컬 실행을 구별합니다. 서버의 AI 원문 검토는 새 환경 실행이나 외부 시스템 성공을 증명하지 않습니다.
- 실제 집행 등 미완료 항목이 남으면 검증 중인 버전으로 기록합니다. 22단계 통과는 원문 검토 기준의 수료이며 운영 인증이나 v1.0 자동 인증이 아닙니다. 서로 다른 커밋의 결과를 한 버전의 성공으로 합치지 않습니다.

## 9. 최종 단계 커밋과 비공개 원문 제출

아래 순서는 이번 단계 안내를 요약한 것이며 Git 명령, 저장소 주소, 커밋 해시를 대신 만들어 주지 않습니다. 실제 제출 화면의 최신 지시를 우선합니다.

1. 학생 문서와 이번 단계 작업을 같은 커밋에 포함합니다. 방어전 상황실 4차 탭의 PowerShell 커밋 안내가 13~22단계를 대상으로 합니다. 이미 준비 중인 변경이 있으면 먼저 내용을 확인하고 기존 작업을 보존합니다.
2. 21·22단계는 과제 화면에서 저장소 주소와 40자리 커밋을 직접 입력하는 절차를 따릅니다. 비공개 저장소를 공개로 바꾸지 않습니다.
3. 비공개 저장소라면 해당 단계의 **「비공개 저장소 원문 준비 방법」**을 열어 **「원문 전달 도구 받기」**를 선택합니다. ZIP과 JSON 출력 폴더는 프로젝트 밖에 둡니다.
4. 제출할 프로젝트의 Git 최상위 폴더에서 PowerShell을 열고, 과제 화면에 제시된 `student-source-cli.mjs` 명령을 사용합니다. 도구 경로·출력 경로·`--commit` 값은 본인 PC와 실제 제출할 40자리 커밋을 확인한 다음에만 채웁니다. 도구는 지정 커밋의 원문을 묶는 절차이며, 학생 앱을 실행하거나 대신 제출하는 명령으로 설명하지 않습니다.
5. 생성된 JSON을 같은 단계의 **「비공개 저장소 원문 묶음」**에서 선택하고 저장소·커밋·단계를 다시 확인한 뒤 제출합니다. 원문 전달 완료와 AI 검토 통과는 다릅니다. 원문 전달만 실패했다면 기존 접수를 유지하고 화면의 **「원문만 다시 보내기」** 절차를 따릅니다.

**이 문서 작성 시에는 실제 Git 최상위 경로, 작업 트리, origin, 제출 커밋을 확인할 수 없었습니다.** 그러므로 개인별 도구 명령과 40자리 커밋은 기입하지 않았습니다. 과제 화면의 정확한 명령과 실제 값을 확인하기 전에는 추정해 실행하지 않습니다.
