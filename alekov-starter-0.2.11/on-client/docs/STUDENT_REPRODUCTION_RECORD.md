> **기록 상태: 검증 중 — 기준 커밋의 로컬 분리 폴더 실행만 확인.** 2026-10-23에 Codex가 아래 기준 커밋을 별도 폴더로 복제하고 시작·브라우저·종료·재실행을 점검했습니다. 학생 본인의 실행 진술은 아직 받지 않았으며 실제 SDP·AI·조치 집행·OSV 조회 성공은 확인하지 않았습니다. 이 문서를 포함할 새 제출 커밋은 아직 확정·재현하지 않았습니다. 서버의 AI 원문 검토는 실행 성공이나 운영 인증의 증명이 아닙니다.

### 값을 확인할 때 지킬 점

- 프로젝트의 Git 최상위 폴더에서 읽기 전용으로 저장소·브랜치·커밋·작업 트리 상태를 확인합니다. 커밋되지 않은 변경이 있으면 덮거나 버리지 말고, 무엇을 제출할지 먼저 직접 검토합니다.
- `origin` URL에 사용자 이름·비밀번호·토큰 같은 인증 정보가 들어 있다면 원문을 문서나 대화에 복사하지 않습니다. 기록에는 인증 정보가 없는 저장소 주소만 남깁니다.
- 이 문서나 앱 코드를 수정했다고 해서 변경 내용이 자동으로 해당 커밋에 포함되지는 않습니다. 문서와 이번 단계 작업은 안내된 제출 절차에 따라 같은 최종 커밋으로 만든 뒤, 그 커밋을 새 폴더에서 확인해야 합니다.
- `git reset`, `git clean`, 기존 폴더 삭제·초기화, 기존 설정 파일의 무작정 복사는 재현 절차가 아닙니다.

## 2. 새 폴더 재현 절차

아래는 **최종 제출 커밋을 확정한 뒤 학생이 순서대로 확인할 절차**입니다. Codex가 실행한 기준 커밋의 결과는 3·4장에 별도로 기록합니다. 비공개 저장소 접근은 본인의 승인된 Git 클라이언트 설정으로 처리하고 비밀번호·토큰을 명령이나 채팅에 붙여 넣지 않습니다.

1. 원래 프로젝트 폴더를 그대로 둡니다. 실제 저장소 URL, 브랜치, 제출할 40자리 커밋을 기록하고, 기존 변경 사항이 있으면 먼저 검토합니다.
2. 원래 프로젝트 밖의 **아직 존재하지 않는 새 폴더 경로**를 정합니다. 아래 명령은 Git 서버에 올린 저장소를 복제하는 예입니다. URL과 경로를 확인하지 않은 채 실행하지 않습니다.

   ```powershell
   $RepoUrl = "<인증 정보가 없는 저장소 URL>"
   $Commit = "<제출할 40자리 커밋 해시>"
   $NewRoot = "<원래 프로젝트 밖의 새 폴더 경로>"

   git clone --no-checkout $RepoUrl $NewRoot
   git -C $NewRoot checkout --detach $Commit
   git -C $NewRoot rev-parse HEAD
   git -C $NewRoot status --short
   ```

   `rev-parse HEAD`가 기록한 제출 커밋과 정확히 일치하고 실행 전 작업 트리가 깨끗한지 확인합니다. 일치하지 않거나 복제·체크아웃이 실패하면 실행 결과를 만들지 말고 원인을 확인합니다. 원격에 올리지 않았다면 원래 프로젝트의 Git 최상위에서 다음처럼 **로컬 복제**할 수 있습니다. 아래 명령 묶음은 아직 실행할 절차이며 이번 문서의 새 제출 커밋 재현 증거가 아닙니다.

   ```powershell
   $SourceRoot = (git rev-parse --show-toplevel).Trim()
   $Commit = (git rev-parse --verify HEAD).Trim()
   $NewRoot = Read-Host '원래 프로젝트 밖의 아직 존재하지 않는 새 폴더 절대 경로'
   if (Test-Path -LiteralPath $NewRoot) { throw '기존 경로를 덮어쓰지 않습니다.' }
   git clone --local --no-hardlinks --no-checkout -- $SourceRoot $NewRoot
   if ($LASTEXITCODE -ne 0) { throw '복제 실패: 여기서 중단합니다.' }
   git -C $NewRoot checkout --detach $Commit
   if ($LASTEXITCODE -ne 0) { throw '체크아웃 실패: 여기서 중단합니다.' }
   if ((git -C $NewRoot rev-parse HEAD).Trim() -ne $Commit) { throw '커밋 불일치' }
   git -C $NewRoot status --short
   ```

   `$NewRoot`가 원래 프로젝트 밖인지 직접 확인한 뒤 실행합니다. 출력이 없다면 커밋 번호가 일치하고 작업 트리에 변경이 없는 것입니다. 복제본을 만드는 명령은 원본의 미커밋 변경을 가져오지 않습니다. 최종 커밋을 정하기 전에 필요한 학생 문서를 빠뜨리지 않았는지 확인합니다. 수료 패키지 내보내기를 선택하면 과제 화면의 실제 도구·절차를 따릅니다.

3. 새 복제본의 앱 폴더는 `alekov-starter-0.2.11/on-client`입니다. `Set-Location -LiteralPath (Join-Path $NewRoot 'alekov-starter-0.2.11/on-client')`로 이동합니다. 기존 폴더의 인증·설정 파일을 복사하지 않습니다. 운영자가 별도 설정 파일을 제공해 사용을 승인한 경우에만 그 설정의 공식 안내를 따릅니다. 필요한 파일은 `package.json`, `student/`, `public/`, `src/`, `vendor/`, `tools/` 및 설명서·비밀 없는 `.env.example`이며, 커밋된 프로젝트 전체를 복제해 함께 가져옵니다.
4. 그 앱 폴더에서 Node.js 버전을 기록하고 아래 실행 도구를 실행합니다. 현재 문서 기준 Node.js 수업 기준은 `24.19.0`입니다. `package.json`은 `24.19.0`을 지정하고 실행 도구는 22~24를 허용하므로, 다른 버전에서 실행했다면 사용한 버전을 실제 값으로 적고 기준 버전과 혼동하지 않습니다. 외부 npm 의존성이 없다고 적힌 현재 `package.json`에는 별도 `npm install` 단계가 없습니다.

   ```powershell
   node --version
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
   ```

5. 실행 도구가 알려 준 로컬 URL을 브라우저에서 직접 엽니다. 기본 주소는 `http://127.0.0.1:5189/`입니다. 서버 응답 메시지는 로컬 서버가 응답했다는 뜻이며 SDP·AI·OSV 등 외부 연결 성공을 뜻하지 않습니다. 기본 연결 없음과 `-Demo` 예제 자료를 실제 연결 결과로 기록하지 않습니다.
6. 관찰한 내용과 시각을 아래 단계 표에 기록합니다. 실제 화면을 보지 못했거나 권한·데이터가 없어 확인할 수 없으면 그 이유를 `미확인`으로 남기고 임의로 오류나 성공 결과를 만들지 않습니다.
7. 실행 창에서 `Ctrl+C`로 종료하고, 같은 새 복제본에서 같은 커밋인지 확인한 뒤 한 번 재실행해 관찰 결과를 기록합니다. 재실행 후에도 제출 커밋이 같은지 확인합니다. 원래 폴더는 계속 보존합니다.

## 5. 데이터·프로젝트 보존 계획과 한계

- **원래 프로젝트 보존:** 원래 폴더와 Git 기록을 삭제·초기화하지 않습니다. 재현은 별도의 새 폴더에서 같은 커밋을 체크아웃해 수행합니다. 실행 전·후 원래 폴더의 변경 사항을 임의로 정리하지 않습니다.
- **미커밋 작업 보존:** 제출 버전에 들어갈지 먼저 검토합니다. 포함해야 하는 변경은 소유자가 안내된 커밋 절차에 따라 저장한 뒤 그 커밋을 기록합니다. 다른 작업은 덮어쓰거나 버리지 않습니다.
- **인증·개인 설정:** 원래 폴더의 설정 파일을 무작정 복사하지 않습니다. 별도 설정이 필요하면 운영자가 승인한 위치와 절차만 사용합니다. 인증서·키·토큰·비밀번호는 Git·이 문서·캡처·제출물에 넣지 않습니다.
- **소스 백업 계획(실행 전):** 커밋된 소스와 Git 기록은 프로젝트 밖의 새 경로에 `git bundle create <백업파일> --all`로 보존하고 `git bundle verify <백업파일>`로 읽을 수 있는지 확인합니다. 경로는 실제 백업 위치로 지정하며 기존 파일을 덮어쓰지 않습니다. 번들은 미커밋·미추적 학생 문서를 포함하지 않으므로 필요한 학생 파일은 검토 후 커밋하거나, 비밀 없는 해당 파일만 별도로 보관합니다. 이번에 번들을 만들거나 복구 시험을 하지는 않았습니다.
- **소스 복원 계획(실행 전):** 원래 폴더에 덮어쓰지 않고 별도 빈 경로에 `git clone <백업파일> <새복원폴더>`로 복원합니다. 기록한 40자리 커밋을 체크아웃하고 `git rev-parse HEAD`, `git status --short`와 파일 대조로 확인합니다. 이는 소스 복원이며 원격 보안 기록·승인·집행 효과 복원이 아닙니다. 백업본에도 비밀 파일·인증 정보를 넣지 않습니다.
- **데이터 위치와 제한(소스 확인):** 본인 보안 기록·기기·세션은 연결된 엔진에서 조회하며 Git 복제에 포함되지 않습니다. `src/actions/store.mjs`는 운영자가 전달한 기존 SQLite `databasePath`에 조치 원장을 추가하지만 기본 실행은 미지원입니다. 이번 실행에는 그 설정을 주지 않았으며 운영 DB를 열거나 백업·복원하지 않았습니다.
- **운영 데이터 백업·복원 계획(운영자 확인 필요):** 실제 데이터의 소유 시스템과 보관 위치를 담당자가 확인하고 쓰기 중단 또는 시스템이 지원하는 일관된 백업 절차를 승인해야 합니다. 실행 중인 SQLite 파일 하나를 복사하는 방식은 검증하지 않았습니다. 감사 원장을 과거 상태로 되돌리거나 조치를 재집행하지 않습니다. 실제 백업·복원 기능과 권한은 미확인입니다.
- **자격 보관 한계:** Windows Vault·호스트 신원은 단순 소스 복제로 이동하지 않습니다. 다른 PC의 인증은 담당자의 승인된 재연결 절차를 따르며 기존 비밀·인증서를 복사하지 않습니다. `.env`는 현재 Git 제외 여부가 보장되지 않으므로 파일명만으로 제출 제외를 가정하지 않습니다. 제출 전 추적 파일 목록을 검토해야 합니다.
- **근거 보존:** 단계별 관찰 시각, 같은 커밋임을 대조한 결과, 안전하게 비밀을 제거한 증거만 기록합니다. 비밀값이 포함된 도움정보나 설정 파일 원문은 기록·공유하지 않습니다.

**실제 응답의 버전 차이:** 도움정보는 `version: 0.1.0`을 표시했습니다. `src/server.mjs`의 `/api/diagnostics` 응답에 이 값이 고정되어 있어 패키지 `0.2.11`과 다릅니다. 학생 함수는 받은 값을 표시합니다. 제공 코드를 고치지 않았으며 이 응답을 앱 패키지 버전으로 해석하지 않습니다.

**이동 가능한 설정과 지원 한계:** `package.json`의 스크립트와 모듈 import는 앱 상대 경로를 사용합니다. 이 앱 폴더에는 외부 npm 의존성과 `package-lock.json`이 없어 이번 실행에서 npm 설치를 하지 않았습니다. OSV 검사는 별도로 운영자가 연결한 프로젝트의 잠금 파일·설치 메타데이터를 대상으로 하므로, 앱에 잠금 파일이 없다는 사실을 취약점 없음으로 보지 않습니다. `.env.example`은 비밀 없는 견본이며 시작 도구가 `.env`를 자동 로드하지 않습니다. 기본 포트는 `ON_PORT` 또는 실행 도구의 `-Port`로 정해지고 브라우저 주소와 맞춰야 합니다. 승인된 외부 호스트 설정이 필요하면 운영자가 새 환경의 실제 경로·권한을 준비해야 합니다. 다른 OS의 Windows Vault 지원, 다른 PC의 인증 이동은 확인하지 않았습니다.

**현재 입력 계약 유지:** `public/app.js`의 `studentData`·`STUDENT_SLOTS`와 `student/extension.mjs`를 대조했습니다. `renderIdentity`는 `me/devices/sessions`, `renderDecision`은 resource와 `appId`, `renderEvents`와 `renderVulnerabilities`는 `status/mode/data/error`, `renderStatus`는 `devices/sessions/notifications/diagnostics/mode`, `renderAiConnection`은 resource와 `checkedAt/explanationAccepted`, `renderExplanation`은 `event/explanation/checkedAt`, `renderAction`은 `status/event/actionId/target/receipt/observation/message/confirmationExpiresAt/error`를 받습니다. 이번 단계에서는 함수·입력·상태·버튼·data-* 속성을 변경하지 않았습니다.

## 7. 제출 전 같은 커밋 확인

학생은 방어전 상황실 4차 탭과 해당 단계 화면의 최신 안내를 우선합니다. 21·22단계는 과제 화면에서 저장소 주소와 40자리 커밋을 입력하는 절차를 따릅니다. 비공개 저장소를 공개로 바꾸지 않습니다. 비공개 원문 전달 도구의 다운로드·명령·출력 위치는 단계 화면의 **「비공개 저장소 원문 준비 방법」**을 따릅니다. 출력 폴더와 JSON은 프로젝트 밖의 새 경로에 두고, CLI에는 실제 제출 커밋을 지정합니다. 원문 전달 성공은 AI 검토 통과와 다르며, 서버 상태와 판정 설명을 별도로 확인합니다.

원래 저장소 URL·브랜치·기준 커밋·분리 폴더는 1장에서 확인했습니다. 다만 과제 화면의 원문 전달 도구 경로·출력 경로·제출할 새 최종 커밋은 아직 확인하지 않았으므로 사용자별 CLI 명령을 만들거나 실행하지 않았습니다. 새 커밋을 만들면 그 커밋으로 분리 폴더를 다시 만들고 해당 커밋의 관찰만 최종 표로 사용합니다. 기준 커밋의 결과와 새 커밋의 결과를 합쳐 전체 성공으로 표시하지 않습니다. 제출 뒤 추가 관찰은 해당 40자리 커밋을 대상으로 기록하고, 이 문서 자체에 자기 커밋 해시가 자동 포함된다고 가정하지 않습니다.
